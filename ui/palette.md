# 팔레트 — AITS 계승

출처: `ANNJUNGCHAN/DAOU.AITradingSystem` → `src/renderer/shared/styles/tokens.css` (다크 블록)
그 파일이 AITS 디자인 토큰의 정본(SSOT)이다. Athena는 **색을 새로 만들지 않고 그것을 계승한다.**

> AITS는 기능이 번잡해서 등지고 온 제품이지만([soul.md](soul.md) §2), **팔레트는 잘못이 없었다.**

Paper 파일에 토큰 43개로 등록해뒀다. 이후 모든 시안은 `var(--color-*)`를 쓴다.

### "액센트 색 없음" 결정의 정정

[round-1R/ranking.md](round-1R/ranking.md)에서 **Athena에 브랜드 액센트 색은 없고 강조는 빛으로 한다**고 정했다.
키움 색을 지킨다는 결정으로 **부분 정정한다.**

**하지만 원래 논지는 살아 있다.** 둘을 이렇게 나눈다:

| | 무엇으로 | 어디에 |
|---|---|---|
| **유리의 상태**(유휴/포커스) | **빛 — 굴절 강도와 광량** | 창 전체 |
| **인터랙션 지점** | **마젠타 `#ee137b`** | 캐럿, 포커스 링, 주 액션 하나 |

즉 **유리는 여전히 무채색이고 틴트하지 않는다.** 마젠타는 유리 위에 놓이는 **점 하나**로만 존재한다.
Apple 규범과도 맞는다 — "틴트는 주요 액션에만 아껴 쓴다."

> 화면에서 마젠타가 보이는 곳은 정확히 하나여야 한다: **지금 입력을 받는 자리.**

### ⚠️ 충돌 — `--color-bad`가 `--color-up`과 같다

둘 다 `#ff5c5c`다. `--color-info`도 `--color-down`과 같은 `#4d9fff`다.

AITS에서는 문제가 아니었을 수 있으나 **Athena에서는 실패 상태 설계의 정면 장애물이다**([round-1R/answer.md](round-1R/answer.md)에서 열어둔 문제).
"TR 호출 실패"를 빨강으로 칠하면 "상승"과 같은 색이 된다. 차트 옆에서 이건 오독을 만든다.

**결론: 오류는 `--color-warn` `#ff9838`(주황)을 쓴다.**
- 가격 의미색과 색상환에서 분리된다
- 주황은 국내 시세 화면에서 가격 의미를 갖지 않는다
- `--color-bad`는 Athena에서 **쓰지 않는다.** 토큰은 남기되 사용 금지

## 타이포그래피 — 다키체

AITS의 `Spoqa Han Sans Neo` / `Pretendard`를 계승하지 **않는다.** Athena는 **다키체**를 쓴다.
사용자 로컬에 설치돼 있고 Paper가 3개 패밀리로 인식한다.

| 패밀리 | 파일 | 용도 |
|---|---|---|
| `Daki` | `DakiL.ttf` · `DakiM.ttf` | 본문 한글, 기본 |
| `Daki B` | `DakiB.ttf` | 강조, 현재 턴의 질문 |
| `Daki Title` | `DakiMTitle.ttf` | 디스플레이 — 큰 가격 숫자 |

### ⚠️ 굵기를 weight로 못 바꾼다

**3개 패밀리 모두 weight 400으로 선언돼 있다.** `font-weight: 700`을 줘도 굵어지지 않는다.
굵기 변경은 **패밀리명 교체**로만 된다 — `font-family: 'Daki B'`.

구현 시 `@font-face`로 weight를 재선언해 정상화할 것을 권한다:
```css
@font-face { font-family: Athena; src: url(DakiL.ttf);     font-weight: 300; }
@font-face { font-family: Athena; src: url(DakiM.ttf);     font-weight: 400; }
@font-face { font-family: Athena; src: url(DakiB.ttf);     font-weight: 700; }
```
`DakiL`과 `DakiM`이 같은 `Daki` 패밀리 안에 둘 다 weight 400으로 들어 있어 **CSS로 L/M을 구분할 수 없다.** 이것도 위 재선언으로 푼다.

### 숫자 — 검증됨, 단 조건부

`글자 대비 — 밝은 배경 적응` 아트보드 하단에 3종 비교 표본이 있다.
다키체 숫자는 예상보다 좋다. `71,400` / `18,402,113` 모두 깔끔하고 `1`의 자족(serif)이 없어 금융 숫자에 적합하다.

**단, tabular figures 여부는 미검증이다.** 실시간으로 자릿수가 바뀌는 호가·체결에서 숫자가 흔들리면 읽을 수 없다.

**따라서 역할을 나눈다:**

| | 폰트 | 이유 |
|---|---|---|
| 큰 가격 숫자 (디스플레이) | `Daki Title` | 존재감이 가장 강하다 |
| 본문 한글 | `Daki` | |
| 강조 한글 | `Daki B` | |
| **정렬이 생명인 숫자** — 호가 사다리, 랭킹 테이블, 타임스탬프, TR 코드 | **`Geist Mono` 유지** | 등폭이 보장된다. 다키체 tabular 검증 전까지 |

다키체가 tabular figures를 지원하는 것으로 확인되면 등폭 사용처를 줄인다.

## 밝은 배경화면 위 가독성

E2/E3에서 유리 뒤는 **사용자 배경화면**이다. 통제할 수 없다.
`글자 대비 — 밝은 배경 적응` 아트보드에서 실측했다.

| | 유리 두께 | 결과 |
|---|---|---|
| **A** | `0.82` (어두운 데스크톱 기준값) | **실패.** 밝은 영역이 유리를 뚫고 올라와 우측 절반의 `--k-dim` 텍스트가 사라진다 |
| **B** | `0.94` + 텍스트 계층 한 단계 상향 | 버틴다 |

Apple은 이 문제를 라이트↔다크 플립으로 푸는데 **Athena는 다크 전용이라 그 수가 없다.**

### 해법 — 어둡게 하지 않는다. **두껍게** 한다 (결정됨)

`유리 · 밝은 배경 해법` 아트보드에서 3안을 비교했다.

| | | 결과 |
|---|---|---|
| **A** 얇은 유리 | 다크 스톱 `0.80` | 밝은 부분이 통과해 텍스트가 씻겨나간다 |
| **B** 불투명 | `0.975` 단색 | 읽히지만 **유리가 아니다.** 검은 판때기 |
| **C** 유리답게 | 아래 4요소 | **읽히면서 유리로 남는다** ✅ |

B는 가독성을 얻고 재료를 잃는다. C는 둘 다 지킨다.
핵심은 **"어둡게"가 아니라 "두껍게"** 라는 것 — 그리고 네 가지가 전부 실제 유리의 물리다.

#### ⚠️ 핵심 — 검정으로 가지 않는다. **환경을 머금는다** (visionOS 방식)

첫 시도는 다크 네이비-블랙(`rgba(16,19,26,0.96)`)으로 눌렀다. 읽히긴 했지만 **그늘이지 유리가 아니었다.**
무드보드 3·7번 핀(visionOS)에서 유리가 방의 온기를 띠고 있던 것이 정답이었다.

> **색조(hue)는 환경에서 가져오고, 명도(luminance)는 고정한다.**

- 따뜻한 배경화면 위 → **따뜻한 토프 프로스트** (`rgba(98,86,72)` 계열)
- 차가운 배경화면 위 → 차가운 슬레이트 프로스트
- 밝기와 무관하게 최종 명도는 **중간-어두움(L\* 30~36)에 착지**한다. 배경이 밝을수록 알파를 올려 같은 명도를 유지

이게 "검정이 아니면서 읽히는" 유일한 지점이다.
**양 극단이 모두 실패한다** — 검정으로 누르면 재료를 잃고, 밝게 두면 등락 적/청과 보조 텍스트가 죽는다. 실측으로 확인했다.

그리고 **어둡되 빛을 받은 것처럼** 보여야 한다:
- 상단 엣지 하이라이트 `rgba(255,253,248,0.80)` — 거의 흰 선
- 유리 내부 warm inner glow `inset 0 0 80px rgba(255,240,214,0.13)`
- 45° specular 스윕

| 요소 | 물리 근거 | 구현 |
|---|---|---|
| **흡수 (absorption)** | 유리는 두꺼울수록 빛을 더 흡수해 어두워진다. 다만 **흡수되는 것은 명도이지 색조가 아니다** — 유리는 뒤의 색을 통과시킨다 | 환경 색조를 유지한 채 알파 `0.74 → 0.875`, **45° 그라디언트** |
| **산란 (scatter)** | 서리유리는 빛을 흩는다. 밝은 핫스팟이 **선명한 반점이 아니라 고른 번짐**이 된다 | 배경의 밝은 덩어리를 넓고 낮은 대비의 워시로 대체 |
| **반사 (specular)** | 배경이 밝을수록 표면 반사가 강해진다 — 물리적으로 맞다 | 상단 엣지 하이라이트 `0.62`까지 강화 + **45° specular 스윕** |
| **각인 (engraving)** | 텍스트가 유리 *위*가 아니라 *안*에 있는 것처럼 | `text-shadow: 0 1~2px 6~10px rgba(0,0,0,0.6~0.66)` |

여기에 **contact shadow**를 더한다 — 밝은 배경 위에 뜬 물체는 그림자가 더 진해 보인다. `0 40px 90px rgba(20,16,10,0.52)`, 색을 순수 검정이 아니라 배경의 따뜻한 톤으로 물들인다.

**부수 효과**: 45° specular가 로고 화살표 각도와 같다([brand.md](brand.md)). 밝은 배경일수록 그 빛줄기가 선명해진다 — 브랜드가 가장 잘 보이는 순간이 가독성이 가장 위험한 순간과 겹친다.

**텍스트 계층은 그대로 한 단계 올린다** — `--k-dim` 자리에 `rgba(244,246,250,0.74)`, `--k-faint` 자리에 `--k-dim`.

#### iOS 26 홈 화면이 같은 답을 낸다

흰 배경화면 위 iOS 26 스크린샷에서 확인한 것:
- **독과 검색 알약이 배경화면보다 어둡다** → 흡수
- **아이콘 라벨에 그림자가 있다** → 각인
- **배지의 채도는 죽지 않는다** → 정보색은 유리가 어두워져도 유지된다

세 번째가 금융 앱에서 가장 중요하다. **등락 적/청을 밝은 배경 유리 위에서 실측했다** (`유리 · 밝은 배경 해법` C안 하단).
`--color-up #ff5c5c` / `--color-down #4d9fff`가 각인 그림자와 함께 채도·가독성 모두 유지된다. **밝은 배경용 별도 등락 색은 필요 없다.**

### 채택 — 배경 밝기를 감지해 적응한다 (결정됨 · **2026-08-19 구현됨**)

> **구현 기록 (2026-08-19).** 현행 스케일로 구현됐다: 창 0.30 → 밝은 배경 최대 **0.72**,
> 캔버스 창 0.50 → 0.72. `app/main.js` `startBackdropSampling()` — desktopCapturer
> 썸네일에서 **자기 창 영역을 제외**하고 평균 휘도 측정(화면 캡처에는 우리 창도 찍힌다),
> 2초 폴링 + EMA 스무딩 + 렌더러 600ms 전이. 폴백: 3연속 실패 시 **0.55 고정**.
> 계산부는 `lib/main/backdrop-luma.js`(단위 테스트 9건). fixture(자동 검증)에선 껐다 —
> 검증16 결정론 보호. 근거: Paper 보드 45 실측(밝은 배경에서 0.30은 dim 텍스트 소실).
> 아래 원문 수치(0.82~0.97, 폴백 0.94)는 하향 이전 스케일의 설계 기록이다.

고정값이 아니라 **감지 후 적응**으로 간다. 유리 두께가 배경 밝기에 따라 `0.82 ~ 0.97` 사이를 오간다.

**구현 부담을 지고 가는 결정이다.** 검증해야 할 것:

- Electron `desktopCapturer`로 창 뒤 영역의 평균 휘도를 샘플링 — **권한 프롬프트가 뜨는지**(macOS 화면 기록 권한). 뜬다면 온보딩에서 설명해야 하고, 거부 시 폴백이 필요하다
- 샘플링 주기 — 매 프레임은 불가능. 창 이동/리사이즈 종료 시 + 저빈도 폴링(예: 2초)으로 충분한지
- 전이 — 두께가 갑자기 바뀌면 깜빡임으로 보인다. 감지값을 스무딩하고 전이를 느리게 걸어야 한다
- **폴백은 반드시 있어야 한다.** 권한 거부·샘플링 실패 시 `0.94` 고정으로 떨어진다. 가독성이 감지 성공 여부에 걸려 있으면 안 된다

> 이건 디자인이 아니라 구현에서 판정된다. 프로토타입에서 권한 프롬프트 여부부터 확인할 것.

## 모션

`--ease: cubic-bezier(.2,0,0,1)` / `--dur-fast: 120ms` / `--dur-base: 180ms`

유리의 굴절 전이는 이 값보다 느려야 한다 — 물성이 다르다. 별도 값이 필요하고 아직 안 정했다.

## 계승하지 않은 것

- **라이트 테마** — Athena는 다크 전용. AITS 라이트 블록은 가져오지 않는다
- **`--gold` 별칭** — `--brand`와 같은 값인데 이름이 오해를 부른다(금색이 아니라 마젠타다). Athena는 `--color-brand`만 쓴다
- **MA 팔레트**(`--ma5`~`--ma120`) — 이평선 캔버스를 만들 때 가져온다. 지금은 불필요
- **`--select` `#5b8dff`** — 드로잉 툴바용. Athena에 드로잉 툴바가 없다
