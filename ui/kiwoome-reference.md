# 키우미 참조 — 알림 오브의 발화 상태

> 원본: `ui/kiwoome.zip` (사용자 제공, 2026-08-24). 압축을 풀면 **키움증권 마스코트
> "키우미"** 3D 렌더 4종이다. 광택 백색 바디 + 딥블루 바이저 얼굴 + 빨강·주황 포인트.
> 압축 해제본과 측정 스크립트는 `ui/.kiwoome-extract/`에 있다(git 미추적).

## 지시와 확정된 범위

사용자 지시(2026-08-24): *"ui\kiwoome.zip 여기있는 이미지 참고해서 오브 다시 만들어줘."*

질의로 확정한 것:

| 물음 | 확정 |
|---|---|
| 반영 범위 | **평소 무채색 → 알림 시 얼굴.** 접힘 기본은 무채색 유리 구체, 미확인 알림이 있을 때만 바이저와 눈이 드러난다 |
| 구현 방식 | **CSS로 다시 그린다.** PNG 에셋을 앱에 넣지 않는다 |

## 왜 이 범위가 규범과 양립하는가

[`ui/brand.md`](brand.md)는 브랜드의 핵심을 *"무채색 구조가 신호가 되는 순간"*이라고
정의한다. 평소 무채색이다가 알림에서만 색이 드러나는 것은 그 문장의 직접 구현이다 —
**색이 장식이 아니라 데이터가 된다.**

바이저는 유리 **위에 칠한 틴트가 아니라** 백색 셸에 뚫린 별개 표면이다. 원본에서도
바이저는 헬멧에 난 창이지 헬멧의 색이 아니다. 그래서 `soul.md` §7의 "유리는
무채색(틴트 금지)"이 그대로 산다 — 유리는 끝까지 무채색이고, 검증이 렌더된 픽셀로
그것을 증명한다(아래).

개정한 조항은 **한 줄**이다: `CLAUDE.md` §2의 "액센트 색 없음" 뒤에 붙인 예외
(오브 창의 발화 상태에 한해 딥블루). 기본 규칙은 지우지 않았다 —
`scripts/gates/check-norms.mjs`가 그 문구의 생존을 고정하고 있다.

## 색 — 원본 실측값 (추측 0개)

원본에는 색 사양이 없다. PIL이 없어 최소 PNG 디코더를 직접 써서
(`ui/.kiwoome-extract/sample-visor.js` — IHDR + IDAT inflate + 언필터) 픽셀을 직접 읽었다.
바이저 픽셀 정의: 불투명(alpha ≥ 220) + 파랑 지배(b > r+45, b > g+45, b > 70).

| 측정 | 값 | 쓰임 |
|---|---|---|
| img3·img4 최빈 | `#080888` | 참고 |
| img3·img4 평균 | `#1A2BBA` | 참고 |
| img4 명도 p05 (최심부) | **`#000984`** | `--color-kiwoome-visor-deep` |
| img4 명도 p50 (중간) | **`#0E20B2`** | `--color-kiwoome-visor` |
| img4 명도 p95 (하이라이트) | **`#576AF9`** | `--color-kiwoome-visor-lit` |

**CSS에 들어간 세 값은 전부 실측이다.** 보간하거나 눈대중으로 고른 값이 없다.
img1·img2의 최빈값(`#6828C8`, `#0828A8`)은 보라 화살표·빨강 소품이 섞여 채택하지 않았다.

## 가져온 것 / 안 가져온 것

**가져온 것** — 76px 원형에 들어가는 **머리**뿐이다.
- 세로로 긴 타원 바이저(폭:높이 ≈ 0.82)
- 흰 둥근 세로 막대 눈 2개
- 상단 스펙큘러 + 하단 인셋 그림자 = 유광 3D 볼륨

**안 가져온 것** (정직 기록)
- **전신** — 팔·다리·포인터·차트판·메달. 76px에 넣으면 아무것도 안 읽힌다.
- **빨강·주황 포인트.** 신호색을 둘로 늘리면 "화면당 신호 한 곳"이 깨진다.
- **PNG 원본.** 앱에 바이너리를 넣지 않는다 — 라스터는 DPI 배율에서 흐려지고
  상태에 따라 변형할 수 없으며 접근성 대비 모드에서도 그대로다.

## 등장 방식 — 페이드가 아니다

`soul.md` §7은 *"페이드로 등장하는 유리"*를 금지한다(유리는 opacity가 아니라 굴절
변조로 나타난다). 그래서 바이저는 **백색 셸이 덮었다가 열리는 기하 변조**로 드러난다:
`clip-path: circle(0%)` → `circle(75%)`.

**첫 구현은 여기서 틀렸다.** `transform: scale(0.34) + filter: blur(7px)`로 눌러뒀는데,
그건 색을 **줄일 뿐 없애지 않았다** — 정지 상태 캡처에서 파란 픽셀 601개, 최대 채도
145가 나왔다. "평소 무채색"은 작게 보인다는 뜻이 아니라 **없다**는 뜻이다.
`clip-path`는 잘린 영역을 아예 그리지 않으므로 정지 상태 파란 픽셀이 0이 된다.

## 검증 — 소스가 아니라 렌더된 픽셀을 잰다

`app/verify.js` 검증 22-A/22-B가 `nativeImage.toBitmap()`으로 실제 BGRA를 읽는다.
소스에 색을 안 썼다는 것과 화면에 색이 안 나온다는 것은 다른 주장이고, 이 저장소는
그 차이로 두 번 데였다(잔류 blur가 데이터를 흐렸고, 죽은 유리 단계가 토큰에만 있었다).

| 상태 | 평균 채도 | 최대 채도 | 파란 픽셀 | 비율 |
|---|---|---|---|---|
| 알림 0건 | **0.59** | **5** | **0** | 0 |
| 알림 1건 | 57.26 | 167 | 4167 | 0.41 |

정지 상태 문턱은 최대 채도 8이다 — 안티에일리어싱 잔여의 여유이고, 바이저는 채도
100을 넘으므로 두 자릿수 차이로 갈린다. 양성 대조군으로 이 오라클이 실패할 수 있음을
확인했다: 정지 상태의 `clip-path`를 열어두니 파란 픽셀 3548개로 정확히 빨개졌다.

## 라이선스 주의

키우미는 **키움증권의 저작물**이다. 이 저장소는 모의계좌 전용이고
(`CLAUDE.md` §1) 원본 PNG를 앱에 포함하지 않지만, 형태를 참조한 것은 사실이다.
외부 배포 전에 사용 허락 여부를 확인해야 한다 — **이 리프에서 확인하지 않았다.**
