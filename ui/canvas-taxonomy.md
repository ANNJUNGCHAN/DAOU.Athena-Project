# 캔버스 분류 체계 (초안)

목표: **키움 288화면을 12개 캔버스 + 자유 캔버스로 접는다.**
근거: [키움 REST API 개발 가이드 (국내주식)](https://openapi.kiwoom.com/m/guide/apiguide?jobTpCode=15) · [비공식 Python 래퍼 — 국내주식 207 엔드포인트 명시](https://github.com/younghwan91/kiwoom-rest-api) · [공식 GitHub](https://github.com/Kiwoom-Securities/Kiwoom-REST-API)

> **주의**: 공식 문서에 TR 총계가 명시되어 있지 않다. 아래 커버율은 총 220개 [추정] 기준의 개산치다.
> 구현 착수 전 Swagger/명세서로 TR별 응답 스키마를 확인해 **캔버스별 필드 매핑표**를 만들어야 한다. 이 문서는 UI 설계용 뼈대이지 구현 스펙이 아니다.

---

## 핵심 발상

TR을 **화면 단위가 아니라 데이터 형상 단위**로 접는다.
288개 화면이 실제로 말하는 문장 구조는 열몇 개뿐이다.

식별된 형상 원형:
시계열 1축 · 시계열 다축 · 랭킹 테이블 · 스냅샷 스칼라 묶음 · 호가 사다리(양방향 막대) · 이벤트 로그 · 2차원 히트맵/트리맵 · 분포 · 폼+상태 테이블

## 자유 캔버스로 보내는 것

자유 캔버스는 실패가 아니라 **설계된 탈출구**다 (soul.md §5-5).

1. **메타데이터/마스터 조회** — 업종코드리스트(ka10101), 회원사리스트(ka10102), 종목정보리스트(ka10099), 관심종목그룹(ka01300/01301).
   → 애초에 시각화 대상이 아니다. 다른 캔버스를 채우기 위한 **참조 데이터**. 드롭다운/설정 패널이면 충분.

2. **조건부 스캐너류** — 신고저가(ka10016), 상하한가(ka10017), 고저PER(ka10026), 거래량갱신(ka10024), VI발동(ka10054), 가격급등락(ka10019).
   → 형상은 랭킹 테이블과 비슷하지만 TR마다 컬럼 조합·정렬 기준·발동 조건이 미묘하게 다르다. 표준 템플릿에 강제로 밀어 넣으면 정보 손실이 크고, 사용 빈도 대비 전용 캔버스 ROI가 낮다.

3. **거래주체/창구 흐름** — 외국계창구매매상위, 당일주요거래원, 거래원별ELW순매매상위.
   → 관계망/Sankey 형상으로 볼 수도 있으나 실수요 검증 전엔 랭킹 테이블 임시 렌더 또는 자유 캔버스가 안전하다.

4. **복합 질의** — "삼성전자랑 SK하이닉스 외국인 순매수 vs PER 같이 보여줘".
   → TR 2개 이상을 조인하는 임시 산점도/이중축. **사전 정의가 원리적으로 불가능하다.** 자유 캔버스가 존재해야 하는 가장 근본적인 이유.

**금현물(kt50000~kt50092)**은 신규 캔버스 불필요. 국내주식과 형상이 같으므로 기존 캔버스에 자산군 라벨·단위 파라미터만 확장한다.

## 미해결

- 캔버스 3개가 한 창에 동시에 살 때의 레이아웃 규칙 — 라운드 2에서 디자인으로 판정
- 자유 캔버스가 얼마나 자주 열려야 "정상"인가의 임계치. **자주 열린다면 캔버스 체계가 틀린 것이다** (soul.md §5-5)
- 실시간 WebSocket 19종(0B 체결, 0D 호가잔량, 0J 업종지수, 1h VI)의 갱신을 캔버스 위에 어떻게 표현할지 — 모션 설계 영역, 아직 손대지 않음
