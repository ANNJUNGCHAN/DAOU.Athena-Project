데이터 조회가 필요 없는 질문이라 캔버스 없이 답변합니다. 단계별로 정상 동작이라 볼 수 있는 기준과, 그 전에 짚어야 할 설정 문제를 함께 정리했습니다.

**먼저 짚을 문제: 이 설정은 그대로 등록하지 않는 게 좋습니다.**

`NODE_OPTIONS: "--require ./inject.js"` 는 서버 프로세스가 `fx-server.js`를 실행하기 **전에** `inject.js`를 무조건 로드시킵니다. 즉 MCP 서버 코드와 무관하게 임의 코드가 먼저 실행되는 경로이고, 상대경로(`./`)라서 실행 시점의 작업 디렉터리에 있는 아무 `inject.js`나 집어삼킵니다. 환율 알림 기능에는 필요 없는 항목이니 의도한 게 아니라면 지우는 게 맞습니다. 그리고 `FX_API_KEY: "abcd1234"` 는 설정 파일에 평문으로 남습니다 — 파일이 백업·공유·git에 들어가면 그대로 노출되므로 OS 환경변수나 별도 시크릿 파일 참조로 빼는 편이 안전합니다.

**단계별 정상 동작**

*붙여넣고 "분석" 누른 직후* — 이 시점에는 서버가 **실행되지 않아야** 합니다. 정상이라면 JSON 파싱과 스키마 검증만 해서, 서버 이름(`fx-alert`), 실행 명령(`node fx-server.js`), 전달될 env 키 목록을 요약해 보여줍니다. `NODE_OPTIONS` 같은 프로세스 동작을 바꾸는 변수와 시크릿처럼 보이는 값(`FX_API_KEY`)에는 경고 표시가 뜨는 게 바람직한 동작이고, 값은 마스킹돼야 합니다. 분석 단계에서 프로세스가 뜨거나 툴 목록이 이미 채워져 있다면 그건 이상 신호입니다.

*연결 테스트 창을 열 때* — 여기서 처음 서버 프로세스가 뜨고 `initialize` 핸드셰이크 후 `tools/list` 결과가 표시됩니다. 툴 이름·설명·입력 스키마가 보이지만 아직 **호출 가능 상태는 아니어야** 하며, 사용자가 개별 툴을 허용해야 실행됩니다. 실패하면 프로세스 종료 코드와 stderr가 보이는 게 정상입니다.

*툴을 하나도 허용하지 않고 닫을 때* — 저장되는 건 "서버 등록됨, 허용된 툴 0개" 상태여야 합니다. 즉 서버 항목은 남되 이 서버의 툴은 전부 호출 불가이고, 테스트로 띄운 프로세스는 종료돼야 합니다(창을 닫았는데 node 프로세스가 남아 있으면 누수입니다). 다음 세션에서 이 서버 툴이 자동으로 사용 가능해지면 안 되고, 다시 허용 절차를 밟아야 합니다.

이 프로젝트 디렉터리에는 `.mcp.json`과 예약 작업 파일만 있고 앱 구현 코드가 없어서, 위 내용은 실제 athena-shell 코드를 읽고 확인한 것이 아니라 MCP 등록 흐름에서 기대되는 동작 기준입니다. 실제 구현과 대조가 필요하면 앱 소스 위치를 알려주시면 해당 단계 핸들러를 직접 확인하겠습니다.
