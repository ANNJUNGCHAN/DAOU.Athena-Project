## 범위와 판단 기준

Codex의 Athena 주 프로젝트에 남아 있던 `Merge completed work branch`,
`완료된 브랜치 병합 및 정리`, `백테스트 paper design 업데이트`의 미처리 사항을
기존 기록, 현재 코드, Git 이력과 새 검사로 대조했다. 다른 프로젝트에 속한 모든

제공되는 도구에 없으며, 보관은 원래 기록을 다시 열 수 있는 처리다.

## 이전의 UI 전수 성공 판정 철회

초기 `CARD-API-SWEEP-closure-20260909.json`의 결측·잘림 0은 시각 검증 근거로 쓸 수 없다.
검사기가 `pending` 영수증과 숨은 `.board-surface`를 받아 로딩 화면의 0 크기 DOM을
측정했다. 이제 최종 `data`/`verified_visible` 영수증을 받고 활성 패널·카드 호스트·표면이
실제로 보일 때까지 기다린다. 첫 응답은 15초, 첫 pending 이후 완료는 제품 계약의 30초이며
반복 pending으로 기한을 늘리지 않는다.

수정 후 전체 101장을 실제로 표시한 검사에서 15장에 결측 228개가 드러났다.
이 수치를 가리거나 임의 데이터로 채우지 않는다. 엄격한 API 화면 게이트는 결측이
존재하면 실패하므로, 코드 통합 완료와 실서비스 전체 승인·게이트 전체 통과를 구분한다.

같은 검사에서 `3GRO-0`의 2분할 배치에 실제 잘림 네 개가 발견됐다. 일반 섹션과 중첩
primary 섹션이 한 nowrap 행에 있고 primary에 100% 폭을 주면서 후자의 표 폭이 0으로
눌린 것이 원인이다. 해당 구조의 가로 부모만 표시하고 M 이하에서 줄바꿈해 필드를
보존했다. 개별 네 폭 재검사에서 잘림은 0, 기존 결측 16개는 그대로다.

## API 결측과 검증의 한계

별도 operation ledger는 101장에 대해 `bound=485`, `mock_unsupported=76`,
`not_a_rest_read=64`, `order_operation_refused=14`, 조회 인자 미매핑 7,
`defects=[]`를 기록했다. 이것은 모든 카드 필드에 실제 값이 있다는 뜻이 아니다.
값 없이 응답한 operation도 49개 있으므로 UI 결측 결과를 별도로 유지한다.

첫 실제 표시 전수 결과는 보드당 결측 표본을 30개까지만 저장해 228개 중 210개 노드만
분류할 수 있다. 그 표본은 모의투자 미지원 193개, 단가(`uv`) 미제공 12개,
선택한 주문번호(`ord_no`) 미제공 4개, 주·보조 operation 사유가 섞인 외화 필드 1개다.
이 분류를 전체 228개의 완전한 설명으로 확대하지 않는다. 주문·체결을 만들거나 계좌
자격을 임의로 바꿔 검사 값을 생성하지 않았다.

## 검증 기록

- API 분류 회귀 20개 및 Ruff 통과. 잘못된 HTTP/응답 코드, 연쇄 소스 오류, 인증 실패,
  금 종목 누락 때 실패를 전파하고 임의 주식으로 대체하지 않는 것을 검증했다.
- 관련 백엔드 회귀 51개 통과(기존 deprecation 경고 1개).
- 최종 표시 대기 회귀 15개 통과. 실제 숨음/표시 전환, pending의 단 한 번 시간 연장,
  timeout과 listener 정리를 실행해 확인했다.
- 중첩 primary 수정 후 board-mount 회귀 87개 통과, 개별 `3GRO-0` 네 폭 마운트 통과.
