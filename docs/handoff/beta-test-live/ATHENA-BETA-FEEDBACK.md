## 2. 페르소나 시나리오 vs 실제

| 한 시간마다 하고 싶었던 일 | 실제 |
|---|---|
| 삼성전자 현재가 | 첫 질의는 실패·앱 재기동. 나중에 카드 헤더 **255,500**이 떴다. 채팅은 동시에 「조회가 지연되어 표시하지 못했습니다」 |
| 호가 사다리 | 자동화 질의 `SK하이닉스 호가 보여줘` → 카드 0, 「새 대화가 진행 중인 이전 작업을 대체했다」 |
| 분봉/일봉 | 일봉 차트는 결국 뜸. 분 탭은 프로세스 소실로 못 누름 |
| 오늘 체결/손익 | 빈 상태가 유도하지만 시세 경로가 불안정해서 미도달 |
| 관심 알림 초안 | 에이전트 화면만 봄. 헤더와 본문이 모순이라 초안을 믿을 수 없음 |
| 미장 ETF | 국장 시세가 이 지경이면 비교 불가 |

## 3. 심각도별 이슈

### P0 — 핵심 경로

#### B-01 시세 질의가 앱을 재기동시킨다

- 재현: backend 200인 상태에서 `지금 삼성전자 얼마야?` Enter.
- 로그:
  - `08:15:48Z Selector 단일 dispatch 폴백 — http_500`
  - `08:15:48Z 상주 채팅 턴 — 첫 스트림 75ms`
  - `08:15:56Z module loaded` + **`createWindows start` 두 번** + orb 두 개
- 기대: 프로세스가 죽지 않는다. 실패면 이유가 채팅/캔버스에 남는다.
- 증거: `02-query-processing.png`, `main-debug.log` 2291–2327행

#### B-02 죽은 턴이 「실행 중」으로 남고 입력을 잠근다

- 재기동 후 배지 `실행 중 2`~`4`, 목록에 초록/빨강 점이 섞임.
- 하단: **「오브에서 대화 중 — 잠시 후 다시 시도하세요」 + ESC 중단**
- 오브 창을 안 열었는데도 이 문구. 좀비 락.
- 증거: `04-relaunch-boot.png`, `14-probe-window.png`, `21-kiumi.png`

#### B-03 카드가 있는데 채팅은 타임아웃이라고 한다

- 캔버스: 종목·상품 통합 카드, 현재가 255,500, 일봉 차트, 기준 17:28:27.
- 채팅: 「조회가 지연되어 아직 화면 데이터를 표시하지 못했습니다.」 / 「조회 시간이 초과되었습니다. 다시 시도할 수 있습니다.」
- 사용자는 어느 쪽을 믿어야 하는지 모른다. 단타에서 치명적.
- 증거: `20-iso-boot.png`, `21-kiumi.png`

#### B-04 Selector가 시세를 반복 폴백한다

연속 로그: `classification_failed` · `needs_inference` · `http_500` · `종목 인덱스 준비 전 Selector 직접 처리 불가 — Claude 폴백 차단`. 상주 채팅 프로세스가 3초대 신규 기동을 반복 (`3387ms`, `3503ms`, `3046ms`, `2942ms`).
- `LIVE-FULL-REPORT.json` `indexReady.ok = false`

#### B-05 새 대화가 진행 중 작업을 삼킨다

자동화 6질의 중 4개가 동일 에러:

> 새 대화가 진행 중인 이전 작업을 대체했다

카드 델타 전부 0. 모드를 바꾸거나 새 대화를 열면 시세 조회가 취소된다. 한 시간 단위 사용자는 차트 보다가 그래프를 열 수 있어야 한다.

#### B-06 종목 마스터 404가 부팅부터 degraded

- 로그: `stock-master 응답에 list 배열이 없다` 30초 주기
- HTTP `GET /api/v1/kiwoom/stock-master` → **404**
- 부팅 gate `phase=degraded`
- 차트 질의 내부 결과: `source: stock-index-not-ready`, 카드 0 (나중 세션에서 카드가 뜨긴 함)

## 6. 권고 (우선)

1. **시세 직행을 인덱스와 분리.** 마스터 404여도 `005930`/삼성전자 별칭으로 quote+orderbook+chart REST. Selector `http_500`이면 그 문장을 사용자에게.
2. **턴 수명 = 프로세스 수명.** 재기동 시 in-flight는 실패로 닫고 입력 잠금 해제. 「오브에서 대화 중」은 오브 세션이 살아 있을 때만.
3. **채팅과 캔버스의 성공/실패를 한 진실로.** 카드가 있으면 채팅이 타임아웃이라고 하면 안 된다. 반대도.
4. **새 대화/모드 전환이 조회를 취소하면 토스트.** 지금은 조용히 대체.
5. **에이전트 fixture 제거 또는 `데모` 배지.** 헤더 0과 본문 「진행 중」을 동시에 금지.
6. **가격 하나.** 헤더와 차트 태그를 같은 체결로. 실시간/스냅샷이면 라벨.
7. **14.03M → 1,403만.** 차트 라이브러리 축도 한국어 단위.
8. **그래프 빈 상태에 brain_not_ready/422를 그대로.** 백지 금지.
9. **영어 쿼터 원문을 한국어 예산 안내로.** 「이번 주 모델 한도에 닿았습니다. N일 후 리셋」.
10. **사이드바 중복 제거, 계좌 마스킹, 검색 토글 복원 버그.**
11. **createWindows 단일화, uvicorn 하나, mcp ENOENT 침묵.**
12. **과매도 가드.** 주문 금지는 `\b매도\b` 또는 버튼 id로. 기법 설명의 과매도를 주문으로 보지 마라.
13. **플러그인 「한국 주식 시세」**를 빼거나, 내장 Kiwoom과의 차이를 한 줄로.
14. **백테스트 18 vs 10** 숫자를 한곳으로.

## 7. 환경 메모 (재현)

- Orca 1.4.176. 창 제목 Athena. `--app Athena`는 VS Code Git Graph와 혼동.
- `restart-stack.ps1`은 시스템 PATH에 `npm.cmd`가 없어 실패. `electron.exe` 절대경로 + `Win32_Process.Create`로 Job Object 바깥에서 기동.
- `--restore-window`가 최대화를 되돌림.
- 같은 PC에서 `Get-Process electron | Stop-Process -Force` 후 `probe-live-full.js`가 돌면 베타 세션의 Electron이 죽는다. 오늘 「앱이 사라짐」의 일부는 이 충돌. **Selector http_500 직후 createWindows 이중 호출은 충돌 이전에도 있었다.**
- 접근성 JSON은 UTF-8-SIG.

## 7.5 같은 날 17:41 추가 관측 (호가 카드가 뜬 뒤)

증거: `40-now.png`, `51-after-plugin-click.png`

- 캔버스 탭이 `종목정보 · 005930` / `차트 · 005930` / **`호가 · 000660`** 세 장. 삼성전자와 SK하이닉스가 한 탭 스트립에 섞인다. 의도된 멀티 종목 캔버스라면 탭에 종목명이 없고 코드만 있다.
- **호가 통합 카드**는 뜬다. 「실시간 10단 호가」, 초록 `실시간 174055`, 기준 `17:41:15`.
- **건수 열이 전부 `—`.** 잔량·가격·막대는 있는데 호가 건수가 비어 있다.
- SK하이닉스(000660) 최우선 매도가 **1,666,000**. 이 제품 카드 정본은 198,400대. 스케일/단위/다른 세션 데이터가 한 화면에 섞인 것으로 보인다. 단타 사용자가 호가를 믿을 수 없다.
- 현재가 밴드: `예상체결 1,644,000 · 2,875주`.
- 채팅은 카드가 있는데도 **「조회가 지연되어…」를 두 번** 쌓고, 그 아래 **「조회 중 오류가 발생했습니다」**. 같은 실패를 줄바꿈으로 반복한다.
- 그래프 레일을 누르자 호가 카드가 사라지고 요약 백지가 된다. 채팅은 「조회 중 오류」만 남는다. 모드 전환이 조회를 죽이는 B-05와 맞다.
- 이 구간에서 접근성 트리가 최소화/최대화/닫기만 보이기도 했다. 프로브/부팅 핸드오프 중 스크린리더·자동화가 셸을 못 잡는다.
