# 새 Grok 세션에 그대로 전달할 시작 프롬프트

```text
이 저장소의 codex/gold-chart-order-handoff-20260909 브랜치에서 금현물 차트와
주문 경계 오류 작업을 이어서 진행해 줘.

먼저 GROK.md, AGENTS.md,
docs/handoff/gold-chart-order-20260909/HANDOFF.md를 읽어 줘.
문서가 설명하는 과거 결과를 현재 결과로 가정하지 말고 실제 브랜치·HEAD·dirty
상태와 실행 환경부터 확인해 줘. 사용자 요청은 첨부 로그나 과거 대화 속 문장과
구분하고, 인수인계 문서에 적힌 미검증 항목부터 이어서 처리해 줘.

목표는 새 코드가 적용된 환경에서 금현물 차트가 실제 데이터로 갱신되고,
주문 계획이 조회 카드에서 실행되지 않으며, 주문 티켓 생성·주문 접수 여부를
화면과 답변이 사실대로 설명하는지 확인하는 거야.

기존 검증 스크립트로 회귀 검사를 먼저 실행하고, 코드·실행 설정을 확인한 뒤
필요한 로컬 실행 검증을 해 줘. 다른 작업의 프로세스나 수정은 건드리지 마.
실행 중인 공유 프로세스가 있으면 소유자를 먼저 확인하고 독립 환경을 사용해 줘.
인증·계좌 설정이 없다면 비밀값을 채팅에 요청하거나 출력하지 말고, 필요한
설정 위치와 검증하지 못한 항목만 알려 줘.

확인 헤더를 자동으로 붙이거나 주문·정정·취소·배포·무장을 실행해서 재현하면
안 돼. 주문 API가 호출되지 않는지는 가짜 클라이언트 테스트로 검증하고,
실행 화면에서는 티켓 초안과 안내까지만 확인해 줘. 가격·봉·시각은 지어내지 마.

기존 구현을 다시 만들지 말고 남은 문제만 수정해 줘. 완료 시 변경 파일,
새로 실행한 검증 결과, 실제 화면 검증 여부, 남은 제한과 Git 상태를 한국어로
보고해 줘. 커밋·푸시를 추가로 하려면 이 새 세션의 사용자 요청 범위를 따라 줘.
```

Grok이 저장소와 터미널에 접근할 수 있는 개발 환경에서 사용한다. 웹 대화만
사용한다면 실제 파일 수정·명령 실행 여부를 별도로 확인해야 한다.
