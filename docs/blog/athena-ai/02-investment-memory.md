# Agentic Memory for ATHENA

Agora · 대화 | Metis · 지식 그래프 | Aegis · 맞춤 감시

## 1. “배당주가 궁금해요”는 보유 사실이 아닙니다

‘삼성전자 배당이 궁금하다’는 관심 표현이고, ‘삼성전자 10주를 보유하고 있다’는 투자 사실입니다. ATHENA는 **Agentic Memory**[^1]를 지식 그래프로 구성해 사람·종목·관심사를 노드로, 그 사이의 의미를 관계로 저장합니다. 대화에서 읽은 관심과 계좌에서 확인한 보유 정보를 처음부터 서로 다른 기억으로 다룹니다.

![관심 표현과 투자 사실을 구분하는 예시](C:/Projects/DAOU.Athena/docs/blog/athena-ai/assets/beginner-05.svg)

## 2. 같은 관계에도 출처와 명시성을 따로 기록합니다

대화는 LLM이 정해진 JSON 형식으로 개체와 관계를 뽑는 **Structured Extraction**[^2]을 거칩니다. 체결·보유 데이터는 LLM의 해석 없이 정해진 규칙으로 그래프에 옮깁니다. 각 관계에는 **Provenance**[^3]를 붙이고, `EXTRACTED`·`INFERRED`·`AMBIGUOUS`로 원문에 얼마나 분명히 드러났는지 기록합니다.

이 구조는 그래프에서 읽어낸 사실과 추론을 구분하고 관계에 근거를 남기는 설계를 투자 맥락에 맞게 적용한 것입니다. ATHENA는 명시성과 출처를 한 점수로 합치지 않습니다. 사용자가 직접 고친 내용과 체결·보유에서 확인한 사실을 대화 추론보다 먼저 적용하고, 요청 ID와 원문 지문이 맞을 때만 추출 결과를 저장합니다.

![대화와 거래 데이터가 서로 다른 경로로 저장되는 과정](C:/Projects/DAOU.Athena/docs/blog/athena-ai/assets/beginner-06.svg)

## 3. 다른 표현이 같은 대상을 가리키면 하나로 정리합니다

‘반도체 산업’, ‘반도체 업종’, ‘반도체’처럼 표현은 달라도 같은 관심사를 가리킬 수 있습니다. ATHENA의 **Entity Resolution**[^4]은 정확한 별칭을 먼저 찾고, 이름 토큰의 Jaccard 유사도가 0.6 이상이거나 이웃 관계의 유사도가 0.8 이상인 후보를 연결합니다. 이웃 관계는 두 대상 모두 연결된 이웃이 2개 이상일 때 비교합니다. 연결된 후보는 Union-Find로 한 묶음을 만든 뒤 관계 수, 별칭 수, 생성 순서에 따라 대표 노드를 고릅니다.

종목은 이름이 비슷하다는 이유로 합치지 않고 종목코드로 구분합니다. 투자자 프로필도 자동 병합에서 제외해, 잘못된 병합이 보유 사실이나 개인화 기준을 다른 대상에 옮기는 일을 막습니다.

![여러 이름을 하나의 대상으로 정리하는 과정](C:/Projects/DAOU.Athena/docs/blog/athena-ai/assets/beginner-07.svg)

## 4. 대화의 관심과 실제 투자 사실을 섞지 않고 기억합니다

이를 통해 ATHENA는 사용자의 질문을 보유 사실로 잘못 기억하거나, 대화만 보고 보유 종목이나 수량을 잘못 기억하는 문제를 **출처별 입력 경로와 우선순위 규칙**으로 해결했습니다. 같은 관심사가 여러 이름으로 나뉘는 문제는 별칭·이름·이웃 관계를 차례로 비교해 하나의 대표 노드로 정리합니다. 정리된 그래프는 메티스에서 근거와 함께 확인하고, 아고라의 다음 대화와 아이기스의 맞춤 감시에 다시 사용합니다.

[^1]: **Agentic Memory**는 에이전트가 이전 대화와 활동을 다음 작업에 다시 사용할 수 있도록 구조화해 저장하는 방식입니다. 단순히 대화 전문을 길게 붙이는 대신, 누구와 무엇이 어떤 관계인지 작은 단위로 나눕니다. ATHENA는 이 기억을 투자자·종목·관심사와 그 관계로 이루어진 지식 그래프에 저장합니다.

[^2]: **Structured Extraction**은 LLM의 자유로운 문장 대신 미리 정한 필드를 가진 결과만 받는 방법입니다. ATHENA는 개체, 관계, 명시성, 근거를 JSON 스키마에 맞춰 추출합니다. 요청 ID와 원문 지문이 다르거나 형식 검사를 통과하지 못한 결과는 그래프에 저장하지 않습니다.

[^3]: **Provenance**는 한 기억이 어디에서 왔는지 추적할 수 있게 남기는 정보입니다. ATHENA는 대화, 체결, 보유, 사용자 수정처럼 출처를 구분하고 관계를 만든 원문과 시점을 함께 보존합니다. 그래서 같은 대상에 서로 다른 정보가 들어와도 어떤 근거를 먼저 적용할지 결정할 수 있습니다.

[^4]: **Entity Resolution**은 표현이 다른 두 항목이 실제로 같은 대상인지 판단하는 과정입니다. **Jaccard 유사도**는 두 집합에서 공통된 항목 수를 전체 항목 수로 나눈 값입니다. 이름에서 나눈 단어나 연결된 이웃이 얼마나 겹치는지 이 값으로 비교합니다. **Union-Find**는 같은 대상으로 판정된 항목들을 하나의 묶음으로 관리하는 방법으로, A와 B가 같고 B와 C가 같으면 A·B·C를 한 묶음으로 정리합니다. ATHENA는 묶음마다 고정된 규칙으로 대표 노드를 선택합니다.
