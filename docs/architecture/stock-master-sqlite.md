# 종목 마스터 저장과 갱신

종목명과 종목코드의 기준 목록은 백엔드 SQLite가 소유한다. Electron과 모델의 종목 식별은 같은 저장소를 사용한다.

## 저장

기본 파일: `~/.athena/instruments.sqlite3`

파일 위치는 `ATHENA_INSTRUMENT_DB_PATH`, 갱신 간격은 `ATHENA_INSTRUMENT_REFRESH_INTERVAL_SECONDS`로 설정할 수 있다. 기본 갱신 간격은 3,600초다.

`instruments`에는 종목코드, 종목명, 검색용 정규화 이름, 시장 코드, 종목 종류를 저장한다. `instrument_metadata`에는 마지막 정상 갱신 시각을 기록한다. 시세와 주문 정보는 이 목록에 포함하지 않는다.

## 갱신 수명

백엔드는 부팅 때 갱신을 시작하고 이후 3,600초 간격으로 백그라운드에서 실행한다. 키움 조회가 가능한 계좌가 준비되어야 수집할 수 있다. 재시작 시 기존 SQLite 목록은 그대로 사용할 수 있다.

시장 0, 10, 8의 목록을 모두 수집하고 검증한 다음 하나의 트랜잭션으로 교체한다. 수집 실패나 불완전한 응답은 마지막 정상 목록을 덮어쓰지 않는다. 처음 실행하여 저장된 목록이 없으면 준비되지 않은 상태를 반환한다.

Electron의 초기 준비 확인은 최대 12초로 제한한다. 첫 수집이 그보다 오래 걸리면 백그라운드에서 준비 상태를 다시 확인하고, SQLite가 준비되는 즉시 부팅 실패 상태를 회복한다. 재확인 간격은 1초에서 최대 10초까지 늘어나며, 준비 완료나 앱 종료 시 중단한다.

## 조회

- `GET /api/v1/instruments/status`: 준비 여부, 행 수, 마지막 갱신 시각.
- `POST /api/v1/instruments/resolve`: `{ "question": "삼성전자 현재가" }`를 받아 일치하는 종목의 코드, 이름, 시장과 종류를 반환한다.
- 일치하는 종목이 없거나 여러 종목으로 해석되면 `instrument: null`을 반환한다.

Electron은 전체 목록을 복제하지 않는다. 현재 질문의 조회 결과만 기존 카드 및 주문 초안 판별에 전달한다. 데이터 조회와 주문 승인 절차는 기존 경로를 따른다.

## 검증 범위

파일 재개방과 재시작, 트랜잭션 교체, 이름 충돌, 초기 실행과 반복 주기, 페이지 이어받기, 실패/빈 목록 보존, 종료 취소, HTTP 조회를 자동 테스트로 검증한다. 테스트는 사용자 DB와 분리된 임시 SQLite 파일을 사용한다.

운영 앱에서 실제 키움 목록을 수집하려면 이 변경을 포함한 백엔드와 Electron을 실행해야 한다. 자동 테스트는 실제 키움 계좌의 수집 성공이나 운영 환경에서 1시간 경과 후 실행한 결과를 대신하지 않는다.

2026-09-08 검증: 백엔드 관련 테스트 98개, 앱 전체 단위 테스트 3,929개 통과. 별도 리뷰에서 이전 질문의 늦은 응답과 테스트 DB 격리 문제를 수정했고, 최종 리뷰에는 추가 수정 요청이 없다. Python 정적 검사와 컴파일, Node 문법 검사, `git diff --check`가 통과했다.

테스트 격리를 적용하기 전 기본 경로에 빈 DB 파일이 생성되었다. 확인 시 종목과 갱신 메타데이터는 모두 0행이었다. 현재 테스트는 임시 경로를 사용한다. 운영 앱 재시작 및 실제 키움 수집은 이 작업에서 실행하지 않았다. 기존 다른 작업의 변경을 보존했고 커밋과 푸시는 하지 않았다.

빈 테스트 DB와 부속 WAL/SHM 파일을 삭제하려던 작업은 자동 승인 검토에서 `blocked by policy`로 거부되어 실행하지 않았다. 파일은 기본 경로에 남아 있다.
