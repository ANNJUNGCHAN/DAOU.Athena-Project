# Athena 외부 고객용 AI 서비스: 대회 평가와 만점을 위한 보완 계획

작성일: 2026-09-10. 참가 부문은 사용자가 지정한 **외부 고객용 AI 서비스**다.

## 결론

**Athena의 우선 과제는 대표 고객 여정 완성, 실제 고객 효과 측정, 사업화 근거 확보다.** 대화·기억·감시를 연결하는 제품 방향과 기술 기반은 강하다. 하지만 기능이 있다는 증거를 고객이 필요로 하고 계속 쓰며 사업으로 확장할 수 있다는 증거로 바꾸는 작업이 필요하다.

만점은 심사위원 판단이므로 보장할 수 없다. 이번에는 실제 고객 연구·완성된 제출자료·현재 앱 실연을 평가하지 않았으므로 총점을 임의로 매기지 않는다. 아래 평가는 **현재 열람한 코드와 문서에 따른 제출 근거의 준비도**이며, 고객 검증 자료를 발견하지 못했다는 것이 실제 고객이 전혀 없다는 뜻은 아니다.

핵심 제안은 다음과 같다.

1. 첫 고객을 한 집단으로 좁히고 그들이 반복해서 겪는 문제를 실제 사례로 제시한다.
2. ‘질문 → 근거 있는 결과 → 내 판단 기억 → 조건 감시 → 다음 방문에서 이어가기’를 실제 앱에서 연결한다.
3. 같은 고객 과업을 기존 방식과 비교해 성공률·소요 시간·근거 정확성·재사용을 측정한다.
4. 고객 유입 경로, 서비스 제공 방식, 사용자당 원가와 확장 계획을 한 장으로 설명한다.
5. 기능 소개와 별도로 15분 발표·5분 Q&A를 준비한다. 본선에서 발표와 Q&A는 30점이다.

## 3. 제품에서 먼저 완성할 일

### P0. 첫 고객과 대표 문제 고정

우선 검증할 고객 가설은 **여러 정보 화면을 오가며 관심 종목을 확인하지만 과거 판단과 관찰 조건을 일관되게 관리하기 어려운 개인 투자자**다. 이는 확정된 고객 조사 결과가 아니다. 모든 투자자·전문가·개발자를 동시에 첫 고객으로 잡으면 문제와 효과가 흐려진다.

검증할 한 문장: ‘Athena는 투자자가 정보를 찾고 판단을 기록하고 이후 변화를 확인하는 일을 하나의 대화 흐름으로 이어주는 개인 투자 작업 공간이다.’

완료 조건: 목표 고객의 실제 반복 과업, 기존 해결 방법, 가장 불편한 순간, 원하는 결과를 한 장에 정리하고 인터뷰 원문 발췌로 뒷받침한다.

### P0. 대표 고객 여정을 끝까지 연결

시연의 중심은 아고라·메티스·아이기스가 이어지는 한 이야기로 둔다. 에르가네는 도구 연결 기반, 글로우는 복귀 경험, 팔라스는 확장 사례로 설명한다. 여섯 모드의 가치를 유지하면서 15분의 중심 줄거리를 만든다.

1. 사용자가 관심 종목의 정보를 요청한다. 출처·조회 시각·실제 데이터가 있는 결과를 받는다.
2. 사용자가 그 결과를 지정해 후속 질문한다. 종목·기간·표시값·대상이 다음 턴까지 정확히 전달된다.
3. 사용자가 판단 이유를 남긴다. 기억에 출처와 확실성 구분이 생기고 잘못 추론한 관계를 확인·정정한다.
4. 사용자가 관찰 조건을 제안받거나 직접 말한다. 지원되는 조건을 검토하고 감시를 설정한다.
5. 실제 충족 이벤트 또는 명시된 재생 이벤트가 알림으로 이어진다. 알림에서 해당 근거와 원래 판단으로 돌아온다.
6. 앱을 다시 열어도 같은 맥락을 이어갈 수 있다.

**가장 먼저 확인하고 보완할 개발 항목은 2번의 결과 참조 대화, 3~5번의 기억·감시 연결이다.** 이미 연결된 부분은 새로 만들지 않고 검증한다. 이 여정에 필요한 화면의 로딩·빈 결과·오류·권한 부족·복구·재시작 상태도 함께 완료한다. 실제로 연결되지 않은 단계는 구현 예정으로 표시한다.

팔라스는 전략 작성→백테스트→결과 해석이 재현될 때 별도 심화 시연으로 사용한다. 과거 성과 수치로 서비스의 투자 수익 개선을 주장하지 않는다. 주문 기능을 보여줄 경우 초안 검토와 실제 실행·접수 결과를 명확히 구분한다. 이 평가 작업에서는 주문·감시·외부 제출을 실행하지 않았다.

### P1. 외부 고객의 첫 사용과 운영 준비

개발자가 없는 환경에서 설치→로그인/연결→첫 질문→첫 유효 결과까지 관찰한다. 필요한 외부 계정, 키 입력, 모델 이용 권한, 데이터 연결 단계를 적고 고객이 실제로 완료할 수 있는지 확인한다. 개발자용 CLI 설정을 고객이 그대로 수행해야 한다면 첫 사용의 감점 위험이다. 기능 추가 전 첫 성공까지 걸리는 시간을 줄이는 것이 우선이다.

기억 확인·정정·삭제, 외부 제공자에 전달되는 데이터, 연결 권한 철회, 제공자 오류 시 복구, 사용량 한도도 고객이 이해할 수 있게 설명한다. 이는 금융 서비스 출시 적법성 판단이 아니라 대회에서 운영 지속성을 입증하기 위한 제품 검증 항목이다.

사업화 자료에는 **외부 고객 제공 전 확인할 사항의 담당자와 상태**도 포함한다. 시장 데이터의 고객 제공·재배포 허용 범위는 실제 이용 계약으로, 개인정보 수집·전송·보존·삭제와 인증·비밀정보 보호는 사내 보안·개인정보 검토로 확인한다. 정보 제공·개인화 설명·투자 판단 지원·주문 실행 각각의 서비스 범위와 책임 경계는 사업·준법 담당 검토 대상으로 구분한다. 검토 전에는 ‘외부 서비스 출시 가능’으로 확정하지 않는다. 이 문서는 개별 법규의 적용 여부를 판단하지 않으며, PoC 참가 요건과 상용 출시 준비도를 구별한다.

## 4. 고객 가치와 혁신성을 숫자로 증명하는 방법

다음 규모와 목표는 **자체 제안이며 공식 만점 조건 또는 이미 달성한 결과가 아니다.** 접수 전 가능한 소규모 관찰을 하고, 예선 준비 기간에는 목표 고객 5~10명 수준의 탐색적 테스트로 확대한다. 소표본 결과를 전체 시장의 통계적 결론으로 일반화하지 않는다.

| 검증 질문 | 과업·측정 | 남길 증거 |
|---|---|---|
| 기존 방식보다 편한가 | 같은 정보·기한 조건에서 자료 확인과 판단 기록까지 완료 시간, 화면 전환 수, 도움 요청 수 | 익명 과업별 기록, 표본 수, 실패·중단 포함 |
| 제대로 해결하는가 | 미리 정한 정답·출처 기준으로 과업 성공률과 근거 정확성 평가 | 채점 기준, 전체 시도 수, 원본 데이터의 시각 |
| 기억이 실제로 필요한가 | 같은 모델·도구·데이터로 기억 사용/미사용 비교 | 과거 판단 재탐색 시간, 맥락 누락·잘못 연결 비율 |
| 다시 쓸 이유가 있는가 | 수일 이상 실제 사용 후 재방문과 반복 과업 사용 | 관찰 기간, 대상자 수, 재사용 이유·이탈 이유 |
| 지속 운영 가능한가 | 고객 과업별 모델 호출·입출력 토큰·재시도·지연·비용 | 제공자 사용량 또는 실제 청구 근거, 추정치 구분 |

기술 차별화의 핵심 실험은 **같은 모델에 개인 기억을 연결했을 때 결과가 달라지는가**다. 구현한 그래프 자체의 우수성까지 주장하려면 일반 대화 기록 검색과도 비교한다. 기능을 끄면서 확인하면 어느 구성 요소가 고객 가치에 기여했는지 설명할 수 있다. 타 서비스보다 낫다는 주장은 동일 과업의 실제 비교를 수행한 범위에 한정한다.

자체 시연 안정화 목표 예시는 대표 여정 20회 중 19회 이상 완료, 잘못된 종목·출처 없는 사실 진술·승인 없는 쓰기 0건이다. 이 수치는 제안된 개발 게이트다. 달성하더라도 전체 정확성이나 안전성을 보장하지 않으며 결과와 잔여 실패를 모두 공개한다. 20회로 p95를 확정적으로 주장하지 말고, 지연 분포와 개별 실패를 함께 확인한다.

## 5. 시장성·사업화 25점에 대응할 자료

**현재 확인 범위에서 가장 우선 보강할 비개발 항목이다.** 좋은 기술과 넓은 기능만으로 고객 확보·사업화 가능성 25점의 근거가 채워지지 않는다. 당장 유료 매출이 필수인 기준은 아니다. 공식 항목은 수익화 또는 고객 확장 가능성을 본다.

한 장에 다음을 연결한다.

| 질문 | 준비할 답·증거 |
|---|---|
| 첫 고객은 누구인가 | 선택한 고객 집단과 인터뷰·테스트 참가자의 실제 특성 |
| 어떻게 고객에게 도달하는가 | 기존 증권 서비스 연계, 한정 베타 초대 등 우선 유입 경로 한 가지와 실행 담당자 |

| 누가 비용을 부담하는가 | 고객 직접 이용형과 계열사 서비스 제공형 중 우선 가설, 고객 계정/회사 제공 모델 비용의 구분 |

원가는 ‘월 과업 수 × 과업당 평균 모델 비용 + 사용자당 배분한 서버·데이터·지원 비용’으로 가정과 실측을 분리한다. 캐시 절감 효과는 실제 호출량으로 증명한다. 고정 구독 비용이나 사용 한도를 토큰 단가로 임의 환산하지 않는다. 사용자 수가 늘어난 세 가지 시나리오를 만들되 확인되지 않은 시장 규모·가격을 사실처럼 적지 않는다.

계열사 확산은 이름을 나열하는 대신 ‘첫 적용 서비스 → 다음 적용 대상의 고객 문제 → 재사용 가능한 부분 → 새로 필요한 연결·운영 비용’으로 표현한다. 논의나 도입 의향이 있다면 확인된 범위의 기록을 첨부하고, 제휴 확정으로 확대하지 않는다.
