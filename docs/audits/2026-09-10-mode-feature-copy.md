## 1. 제안하는 구성

**글로우를 포함한 여섯 제품 표면을 각각 하나의 소개 페이지로 만든다.** 사이드바의 다섯 모드와 독립 창인 글로우를 같은 제품 소개 수준으로 다룬다. 각 페이지는 이름과 한 문장의 소개, 화면 이미지가 붙는 메인 기능 2~5개, 아이콘이 붙는 서브 기능 3~5개로 구성한다. 기능 수를 채우기 위해 같은 기능을 이름만 바꾸어 반복하지 않는다.

참고 페이지를 현재 공개 본문에서 확인했다. [Antigravity 2.0](https://antigravity.google/product/antigravity-2)은 메인 5개와 서브 3개, [CLI](https://antigravity.google/product/antigravity-cli)는 메인 2개와 서브 5개, [IDE](https://antigravity.google/product/antigravity-ide)는 메인 4개와 서브 3개다. 이번 제안은 이 정보 위계를 참고하며 이미지의 세부 스타일을 복제하는 작업은 포함하지 않는다.

큰 이미지에는 버튼 하나보다 사용자가 일을 마친 상태를 담는다. 예를 들어 차트 도구 아이콘보다 실제 지표를 얹은 차트, 플러그인 로고보다 연결된 기능과 허용 범위를 보여준다. 문구는 `제목 → 사용자가 얻는 결과 → 실제 조작` 순서로 쓴다.

### 조사 범위와 증거의 의미

- 현재 체크아웃의 `app`과 `backend`에서 모드 진입점, 렌더러, IPC, API/MCP, 서비스와 관련 테스트를 기능별로 추적했다. 파일 목록만으로 기능을 인정하지 않는다.
- 사이드바의 다섯 모드는 `app/shell.html:112,119,129,139,147`과 `app/lib/sidebar.js:55`에서 확인한다. 코드의 내부 키 `summary`는 제품에서 **아고라 · 대화**로 표시된다. **글로우**는 사이드바 밖의 독립 제품 표면이며 `app/orb.html`, `app/orb.js`와 메인 프로세스의 창 제어를 함께 조사한다. 사용자 지정을 따라 페이지 이름은 글로우로 쓰고, 코드에 남은 orb·글라우 식별자와 구별한다.
- 이 문서는 전 모드의 사용자 기능을 대상으로 한 **정적 코드 조사와 원고 초안**이다. 저장소의 모든 줄을 정독했다거나 모든 화면·외부 연동을 실행 검증했다는 뜻은 아니다. 테스트 파일은 계약 확인 자료이며 이번 조사에서 실행 통과를 주장하지 않는다.
- 아래의 원고는 코드에서 확인한 경로를 토대로 한다. 계좌·데이터 공급자·AI 로그인·서버 연결에 의존하는 기능은 실제 촬영 전에 연결 상태와 실행 결과를 확인해야 한다. 화면이 있다는 이유만으로 실거래·성능·항상 가용함을 보증하지 않는다.
- 기획 문서와 Paper 테스트 시나리오는 보조 자료다. 실제 동작 경로가 확인되지 않는 부분은 홍보 확정 대상에서 제외하거나 조건을 적는다.

**문구 제한:** 글로우도 여섯 페이지 중 하나로 같은 비중을 갖는다. 내부적으로는 독립 orb 창이며 전체 화면의 모든 기능을 그대로 복제하지 않는다. 미니 차트는 전체 분석 차트와 달리 최소 데이터 조건을 만족하는 종가 라인 중심이다. 루틴 생성·감시 승인·취소는 전체 화면에서 처리하는 경로와 구별한다(`app/orb.js:33`). 전체 창을 여는 동작만으로 대화 내용 전체가 자동 이전된다고 약속하지 않는다. 표정만으로 숫자나 오류 상세를 대체하지 않는다.

각 페이지를 5개 메인으로 맞추지 않는다. 에르가네는 연결·권한·관리라는 세 경험으로 충분하다. 글로우는 다른 다섯 페이지의 부록으로 축소하지 않는다. 전체 소개에서는 아고라 → 메티스 → 아이기스 → 에르가네 → 팔라스 → 글로우 순서로 안내하고, 독립 페이지에서는 원하는 기능으로 바로 진입하게 한다.

### 다음 제작 단계

1. 이 문서의 **페이지 제목·페이지 본문**을 실제 원고로 사용한다. `실제 세부 기능`, 코드 근거와 문구 제한은 내부 기획·검증 자료다.
2. 각 메인 ID에 현재 앱 화면을 대응시킨다. 연결 준비가 필요한 기능은 성공 상태와 그 상태를 만든 절차를 먼저 확인한다. 이미지 촬영 때문에 주문·삭제 등 실제 부작용을 발생시키지 않는다.
3. 큰 이미지에는 완성된 결과와 한 가지 핵심 조작을 담는다. 도표와 금액을 임의로 꾸며 현재 앱의 결과처럼 사용하지 않는다. 설명용 샘플이 필요하면 샘플임을 표시한다.
4. 실제 화면에서 제목이 말하는 행동을 재현한 뒤 원고를 확정한다. 빈 상태·로딩·실패·승인·비활성·연결 끊김은 각 기능의 검토 항목으로 남기되 모두 홍보 카드로 만들 필요는 없다.
5. 그 다음 페이지 레이아웃과 이미지 구성을 제작한다. 이번 작업은 원고와 조사 문서 작성이며 제품 코드·Paper 보드·웹사이트는 변경하지 않는다.

## 10. 검증 기록

조사 기준은 저장소의 현재 HEAD이며 외부 서비스 실행 검증과 배포 승인은 포함하지 않는다. 모드별 코드 조사 후 원고를 작성하고, 별도 검토자가 핵심 문구와 현재 소스를 대조했다. 글로우의 “이어보기”가 대화 자동 이전으로 읽힐 수 있다는 지적을 반영해 “전체 화면 열기”로 수정했다. 알림 대표 카드 전송과 대화 창 열기를 구별한다(`app/main.js:2125,5472`; `app/orb.js:2352`).

문서 구조 검사에서 6페이지 모두 메인 2~5개·서브 3~5개 범위를 충족했고, 합계는 메인 25개·서브 24개다. 검사 당시 명시된 62개 소스 참조의 파일 존재와 시작 행 범위를 확인했으며, 문서에 행 끝 공백은 없었다. 저장소 변경은 이 문서 한 파일이며 제품 코드는 수정하지 않았다. 제품 테스트와 라이브 화면 검증은 이번 정적 원고 조사에서 실행하지 않았다.
