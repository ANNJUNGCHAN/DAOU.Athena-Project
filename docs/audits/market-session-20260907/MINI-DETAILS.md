## 재현과 판정 규칙

장전 baseline에서 아래 명령이 paper suite의 하위 단계로 실행됐고, 의도대로 불일치를 보고한 뒤 exit code 1을 반환했다.

~~~powershell
Set-Location app
npm run verify:paper-mini-static
~~~

판정은 라벨이 아닌 fixture 값 문자열을 비교한다. 각 상세 행의 R1은 위 명령을 뜻한다. 유형은 다음과 같다.

| 코드 | 실제 관측 | 기대/차이의 뜻 | 영향 |
| --- | --- | --- | --- |
| FORM | Paper 값이 대장 값과 완전 일치하지 않고 부분 문자열로만 일치 | 같은 데이터의 표기 형식 차이 | 표시/파서 계약이 달라질 수 있음 |
| STALE | Paper가 해당 보드의 슬롯에는 있으나 현재 대장 선택값에 없는 값을 표시 | Paper 표시 슬롯과 대장 선택 슬롯 불일치 | renderer의 원천 선택에 따라 내용이 달라질 수 있음 |
| UNBACKED | Paper 값이 대장이나 96개 보드 슬롯 역색인 어디에도 없음 | 근거 없는 fixture 표시값 | runtime 데이터 출처 추적 불가 |
| CROSS | Paper 값이 대상 대장 보드에는 없고 다른 보드에만 있음 | 다른 카드 값 혼입 가능성 | 잘못된 카드 내용 복사/연결 가능성 |
| MISSING | 대장 요소가 Paper 실카드에 없음 | 대장 정의 요소의 Paper 누락 | 노출 정보 누락 또는 계약 범위 불일치 |

모든 상세 행의 판정 한계 L1: 정적 fixture 문자열/구조 대조만 증명한다. 실제 앱이 어떤 원천을 렌더링하는지, 장중 값이 갱신되는지, 주문·계좌·호가·차트 상호작용이 작동하는지는 증명하지 않는다. 수정 전 root 진단에서 Paper 원장, 대장, renderer 중 어느 쪽이 현재 제품 계약인지 다시 확인해야 한다.

## 후속 root 진단 기준

77개 실카드와 94개 주석을 곧바로 제품 결함으로 일괄 수정하면 안 된다. 후속 진단은 먼저 CROSS 10행의 실제 소유 보드를 확인하고, 그 결과가 0이 된 뒤 FORM/STALE/UNBACKED/MISSING의 정본을 카드별로 결정해야 한다. 각 수정은 해당 카드의 Paper H-1 tree/json, <code>kiumi-ledger.jsonl</code>, <code>card-surface-templates/&lt;id&gt;/slots.json</code>, renderer 출력의 네 원천을 함께 대조한다. 이후 <code>verify:paper-mini-static</code>을 재실행하고, Electron runtime probe가 셸 handoff를 완료한 새 증거와 실제 장중 read-only 관찰이 있어야 장중 정상/불량 판정을 갱신할 수 있다.
