# ATHENA 100점 달성 계획: AI 기술 반영 적합성 검토

검토일: 2026-09-10

## 판단

**세 기술 분야는 계획에 잘 맞습니다. 그러나 ToolRerank·A-MEM·HippoRAG를 모두 새로 도입하는 것을 만점 달성의 선행 조건으로 두는 것은 권하지 않습니다.**

가장 가치 있는 기술 축은 **출처가 남는 투자 기억을 다음 행동까지 연결하는 것**입니다. 기존 도구 선택과 그래프 검색은 그 경험을 정확하고 안정적으로 완성하는 기반입니다. 현재 부족한 증거를 확보한 뒤, 실제 실패 원인을 해결할 수 있는 논문 기법을 선택하는 순서가 맞습니다.

이번 검토는 ‘현재 구현된 세 분야의 활용’과 ‘세 논문의 추가 도입’을 구분합니다. 관련 작업 **「Athena 100점 달성 계획」**과 그 [보완 계획 문서](C:/Projects/DAOU.Athena/docs/audits/2026-09-10-competition-external-service-gap-plan.md), [알고리즘 구현 검증](C:/Projects/DAOU.Athena/docs/audits/2026-09-10-blog-core-algorithm-verification.md)를 대조했습니다. 기존 계획과 블로그는 수정하지 않았습니다.

## 1. 평가 기준에 얼마나 직접 기여하는가

아래 배점은 기존 계획에 정리된 외부 고객용 부문 예선 서류 기준입니다. 기술 도입만으로 해당 점수가 확보된다는 뜻은 아닙니다.

| 평가 영역 | 배점 | 이번 기술의 기여 | 필요한 증거 |
|---|---:|---|---|
| AI 활용 혁신성 | 25 | 개인 기억·근거·행동을 연결하는 제품 차별성 설명에 적합 | 동일 모델에서 기억 또는 그래프를 사용할 때 고객 과업이 개선되는 비교 |
| 고객 가치·문제 정의 | 25 | 과거 판단을 다시 찾고 반복 설명을 줄이는 경험에 직접 연결 | 실제 목표 고객의 불편, 재탐색 시간·정정량·과업 성공률 |
| 프로토타입 구현 수준 | 25 | 도구 호출과 기억 조회의 실제 동작, 오류 복구를 뒷받침 | 대표 여정의 현재 빌드 실행, 실패·재시작까지 포함한 증거 |
| 시장성·사업화 가능성 | 25 | 비용·재사용 경험에 간접 기여 | 고객 유입·재방문·지불 의향 또는 고객 확장 효과·운영 원가 |

본선에서는 핵심 성과·완성도 35점, 발표·Q&A 30점, 파급력 25점, 운영 지속성 10점에 맞춰 입증해야 합니다. 논문을 많이 설명하는 것보다 ‘왜 이 고객에게 이 설계가 필요한가’를 실행과 비교 결과로 보여주는 편이 계획에 부합합니다. [배점과 기준](C:/Projects/DAOU.Athena/docs/audits/2026-09-10-competition-external-service-gap-plan.md:23)

## 2. 현재 기술을 어떻게 계획에 넣을 것인가

### 최우선: 출처 기반 투자 기억 + 후속 행동

이 축은 기존 계획의 혁신성·고객 가치 실험과 가장 직접적으로 연결됩니다.

대표 경험은 다음과 같습니다.

**종목 정보 조회 → 결과를 가리켜 질문 → 판단 이유 기록 → 잘못된 기억 정정 → 지원되는 관찰 조건 설정 → 알림에서 원래 판단과 근거로 복귀**

현재 검증된 구조화 추출, 출처·명시성 구분, Jaccard·Union-Find 통합을 이 흐름의 기반으로 사용합니다. 그러나 알고리즘의 존재만으로 결과 참조 대화나 기억→감시 연결이 완성되었다고 판단하지 않습니다. 기존 계획도 이 연결을 먼저 확인하라고 명시합니다. [우선 개발 항목](C:/Projects/DAOU.Athena/docs/audits/2026-09-10-competition-external-service-gap-plan.md:85)

고객이 ‘무엇을 기억했는지’를 볼 수 있고, 잘못된 관계를 정정한 뒤 다음 응답에서 반영된 것을 확인할 수 있어야 합니다. 감시는 이미 지원되는 조건과 확인 절차를 사용하고, 제안·설정·이벤트 발생을 각각 구분해서 시연합니다.

### 기반 완성: 도구 선택과 실행 품질

어휘·조건 기반 selector, 검증된 제안의 단일 실행, 차트 데이터 연결은 시제품 완성도를 위한 중요한 기술입니다.

지금 필요한 일은 이 구조를 또 만드는 것이 아니라 **어디에서 실패하는지 측정하는 것**입니다. 실패를 후보 누락, 후보 선택 오류, 인자 오류, 데이터 제공자 실패, 화면 연결 오류로 나눠야 합니다. 재정렬 모델은 마지막 세 종류를 해결하지 못합니다.

병렬 분류도 자동으로 정확도를 높이는 방식은 아닙니다. 첫 유효 응답이 의미상 정답인지, 추가 호출 비용에 비해 유효 화면 표시가 빨라지는지 검증해야 합니다.

### 차별화 보조: 그래프 근거 검색과 의미 라벨

BM25, 관계 조회, 군집화, 숨은 연결 점수, LLM 군집 라벨은 ‘개인의 투자 맥락을 읽을 수 있게 한다’는 시연에 적합합니다.

다만 군집 그림이나 이름 자체를 고객 성과로 삼지는 않습니다. 사용자가 과거 판단을 빨리 찾고 원문을 확인할 수 있는지가 핵심입니다. 차수·이벤트 수를 추천 정확도나 선호 학습 성과로 표현하지 않습니다.

## 3. 세 논문은 도입할 가치가 있는가

| 기술 | 적합성 판단 | 시작할 조건 | 권장 범위 |
|---|---|---|---|
| ToolRerank | 조건부 적합 | 유사 API가 많아 정답 후보 누락·선택 오류가 반복되고, 해당 오류가 고객 과업 실패의 주요 원인일 때 | 기존 selector와 오프라인 후보 검색·재정렬 비교 |
| A-MEM | 일부 아이디어는 유용, 전체 도입은 후순위 | 장기간 대화에서 별칭·문맥 연결 실패가 실제 문제이고, 기존 추출·중복 통합 개선으로 부족할 때 | 원문을 보존한 파생 설명·관련 기억 링크부터 격리 실험 |
| HippoRAG | 여러 관계를 거치는 근거 질문에 조건부 적합 | 단순 이름 검색으로 찾기 어려운 다중 관계 질문이 실제 고객 과업에 충분히 존재할 때 | 읽기 전용 그래프 검색 비교 후 PPR·인덱싱 확장 여부 판단 |

**ToolRerank:** seen/unseen은 학습 데이터의 도구 이력이며 MCP 연결 가능 여부와 다릅니다. 학습된 검색기·재정렬기와 도구 계층을 포함한 설계이므로 단순 후보 제한만 추가하고 논문 구현이라고 부를 수 없습니다. 후보에 정답이 없으면 현재 top-3 내부의 재정렬만으로 복구되지도 않습니다. [원문](https://aclanthology.org/2024.lrec-main.1413/)

**A-MEM:** LLM이 기억을 연결하고 파생 문맥을 갱신하는 방법입니다. ATHENA의 거래·보유 사실 및 수동 정정을 자동 갱신 대상으로 확대하면 기존 출처 규칙과 충돌할 수 있습니다. 선택적으로 연구하되 원문·확정 사실과 파생 해석을 분리해야 합니다. A-MEM 전체 도입 없이도 현재 기억 구조의 효과를 먼저 검증할 수 있습니다. [원문](https://arxiv.org/abs/2502.12110)

**HippoRAG:** 질문 엔티티를 출발점으로 그래프를 탐색해 문단을 회수합니다. 단순한 ‘삼성전자 관련 내 대화 찾기’보다 여러 관계에 걸친 근거 회수에 실험 가치가 큽니다. 기존 그래프에 PPR만 붙인 실험은 HippoRAG 전체 재현과 구분해야 합니다. 노드와 원문 연결, 관계 품질, 시간·사용자 범위가 먼저 정리되어야 합니다. [원문](https://arxiv.org/abs/2405.14831)

세 논문 중 하나를 무조건 우선 채택하기보다는 **고객 과업에서 가장 큰 오류를 만드는 단계**에 따라 선택하는 것이 맞습니다. 논문의 공개 성능을 ATHENA의 기대 개선률이나 대회 예상 점수로 환산하지 않습니다.

## 4. 계획에 추가할 실행 묶음

다음은 제안된 작업·완료 기준이며 공식 만점 조건이나 달성 결과가 아닙니다.

| 순서 | 작업 | 완료 증거 |
|---|---|---|
| P0-1 | 대표 고객 과업과 실패 단계 정의 | 입력·원문·시각·기대 결과·성공 판정이 있는 과업 묶음 |
| P0-2 | 결과 참조 → 기억 확인·정정 → 감시·복귀 연결 검증 | 동일 빌드의 연속 시연, 실패 사례, 재시작 후 상태 |
| P0-3 | 기억과 그래프의 기여 비교 | 아래 A/B/C 조건별 과업 결과와 원본 기록 |
| P0-4 | 모델 호출·재시도·화면 표시 지연·비용 계측 | 과업 ID로 연결한 로그, 제공자 실제 사용량, 추정·실측 구분 |
| P1 | 실패 원인에 맞춘 기존 알고리즘 개선 | 변경 전후 고정 평가집 비교, 회귀와 추가 비용 |
| P2 | ToolRerank 또는 PPR 등 한 후보만 격리 실험 | 기존 방식보다 개선되는 과업·조건과 악화되는 조건 |
| 병행 필수 | 고객·사업성 증거 확보 | 목표 고객 관찰, 유입 경로, 재사용 이유, 원가와 비용 부담 가설 |

### 가장 먼저 할 기술 실험

- **A: 개인 장기 기억 없음.** 같은 모델·도구·현재 질문을 사용합니다.
- **B: 일반 대화 기록 검색.** 같은 원본 대화에서 관련 기록을 찾아 제공합니다.
- **C: 현재 ATHENA 그래프 기억.** 출처와 관계를 회수해 제공합니다.

A와 C의 비교는 ‘기억이 도움이 되는가’를, B와 C의 비교는 ‘그래프로 조직한 것이 추가로 도움이 되는가’를 봅니다. B가 현재 제공 기능이 아니라면 오프라인 평가용 비교 조건으로만 준비하고 출시 기능이라고 표시하지 않습니다.

모델·데이터 시점·사용 가능한 원문·컨텍스트 예산을 맞추고, 질문 유형과 사용자 이력을 분리해 평가합니다. 같은 자료로 규칙을 조정하고 성과를 측정하는 누수를 피합니다. 온·오프 조건이 바뀌며 정답이 달라지지 않도록 정답 근거를 먼저 확정합니다.

평가 항목은 과업 성공률, 근거 정확성, 과거 판단 재탐색 시간, 잘못된 기억 연결·누락, 사용자 정정량, 모델 호출·토큰·비용입니다. 병렬 분류는 단일 분류기와 별도로 비교합니다. 소표본 고객 관찰과 대규모 반복 실행의 지연 지표를 섞어 해석하지 않습니다.

승격 기준은 실험 전에 정합니다. 고객 과업 개선 없이 비용과 지연만 늘어나면 신규 알고리즘은 보류합니다. 잘못된 종목·오래된 사실·정정 무시 등 중요한 오류가 생기면 평균 점수 상승만으로 통과시키지 않습니다. ‘관측 0건’은 시험한 범위의 결과로 보고합니다.

## 5. 발표에 쓸 기술 메시지

권장 중심 메시지:

> ATHENA는 투자 정보를 조회하는 대화와, 과거 판단을 근거와 함께 다시 활용하는 과정을 연결합니다. 출처가 남는 기억과 검증된 도구 실행이 실제 고객 과업에 얼마나 기여하는지 같은 조건에서 비교합니다.

비교 실험이 완료되기 전에는 ‘개선했다’가 아니라 ‘검증할 구조를 갖췄다’고 설명합니다. 발표의 기술 부분은 **문제 한 장 → 실제 처리 구조 한 장 → 고객 과업 비교 결과 한 장**이면 충분합니다. 논문은 해당 선택의 비교 근거로 연결하고, 미구현 알고리즘의 이름을 현재 서비스의 성과처럼 내세우지 않습니다.

이 기술 작업은 만점 준비의 일부입니다. 기존 계획에서 공백으로 지적한 고객 검증·사업화·통합 완성도·발표 근거가 남으면 새로운 AI 기법을 도입해도 그 공백은 남습니다. 이번 검토에서는 점수를 새로 산정하거나 100점 달성을 보장하지 않습니다.

## 검토 범위

기존 계획의 배점·우선순위와 이번 세 기술의 구현 검증을 대조한 계획 검토입니다. 원 대회 PDF의 최신 개정·일정·제출 허용 범위를 재검증한 문서는 아닙니다. 새 코드 구현, 성능 실험, 고객 테스트, 다른 작업에 대한 메시지 전송은 수행하지 않았습니다.
