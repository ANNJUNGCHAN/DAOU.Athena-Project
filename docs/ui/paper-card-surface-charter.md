## 0. 요지

op 단위 표현은 299/299(100%)에 도달했지만, 응답 **필드** 단위로는 가시 3,534개 중 표현 1,851(52%) · 집약 589(17%) · 미표현 1,094(31%)다.
다음 목표는 **필드 표현 100%**이고, 조건은 "나열이 아니라 한눈에"다. 이 둘은 상충하지 않는다 — 문제는 양이 아니라 **위계와 자리**다. 모든 필드에 글자 그대로의 자리를 주되, 그 자리를 세 층(직접·병기·펼침)으로 나눠 메인 표면의 밀도 예산을 지킨다.

## 2. 목표 정의

### 2.1 모수와 목표

```
필드 점유 3,705
 = 비노출 173  (전송·내부 171 + 예비 슬롯 2 — 그릴 대상이 아님, 명문 계정)
 + 가시 3,532  ← 이 전부에 "글자 그대로의 자리"를 준다 (2026-09-02 15:45 표현 100% 달성 · op 299/299)
```

**목표: 가시 3,532 필드 표현 100% · 집약 0.** — 달성(직접 2,617 · 병기 630 · 펼침 285). 집약(합계·대표값에 흡수)은 인정하지 않는다.

**비노출 명문 계정 2종.** 아래 두 부류만 "그릴 대상이 아님"으로 계정 처리한다. 그 밖의 어떤 필드도 이 계정으로 옮길 수 없다.

| 부류 | 건수 | 근거 |
|---|---|---|
| 전송·내부 | 171 | 요청 헤더·페이징 커서·응답 코드 등 사용자 의미가 없는 전송 계층 |
| **예비 슬롯** | **2** | `base:04` 실시간 체결 응답의 `951`·`924`(Extra Item). 이름·단위·사용자 의미가 정의되지 않은 미할당 슬롯이며 값이 항상 공란이다. 표면 요소를 만들면 신념 8(`기타` 몰아넣기)과 신념 9(이름 있는 화면) 위반이다. 정의가 부여되는 시점에 가시로 되돌린다 |


### 2.2 "표현"의 세 층

| 층 | 정의 | 예 | 실앱 대응 |
|---|---|---|---|
| **직접** | 값이 개별 시각 요소(컬럼·행·라벨·게이지·칩·캔들)로 그려짐 | 표의 `거래량` 열 | 렌더러 열 |
| **병기** | 같은 셀 안 두 번째 줄(text-xs·k-dim)로 그려짐 | `+1,850` 아래 `+1.24%`, 종목명 아래 `005930` | 셀 템플릿(주값+보조값) |
| **펼침** | 메인엔 합계 셀, 펼침 상태 보드에 낱값 표 | `매매 비용 -24,600` ▸ 세금 7종 분해 | 접힘/펼침 토글 하나 |

세 층 모두 필드에 고유한 자리가 있으므로 표현이다. "레일 블록에 뭉뚱그려 넣기"와 "합계만 남기기"는 표현이 아니다.

### 2.4 성공 판정

- 필드 원장(가시 3,532행)이 표현 100%이고, 각 행에 `보드 id · 층(직접/병기/펼침) · 위치` 근거가 있다.
- 메인 보드 전부가 밀도 예산 안이다(스크립트 검사 가능 항목: 열 수·KPI 칸·레일 블록·높이).
- 문구 3원칙 위반 0, 정본 정합 위반 0, 잘림·겹침 0.
- 마일스톤마다 사용자 스크린샷 검수 승인.

### 3.1 밀도 규칙 — 영값 묶음 (2026-09-02 사용자 승인)

정보를 빼지 않고 밀도를 낮추는 네 가지 규칙. 레일·펼침 보드·낱값 보드 전부에 적용한다.

| 규칙 | 내용 |
|---|---|
| **H1 영값 묶음** | 한 블록에서 값이 0원·해당 없음·미제공인 항목이 **3개 이상**이면 항목명을 나열한 한 줄 `신용융자·현금미수·대출·연체·담보·대여 — 0원 6항목 ▸`로 접고, 낱값은 펼침 보드에서 보인다(필드는 펼침 층으로 이동, 표현 유지). 값이 생기면 그 항목만 자동으로 행으로 올라온다. 펼침 보드 안에서는 다시 접지 않고 행으로 두되 k-faint로 가라앉힌다 |
| **H2 값 우선 정렬** | 판단에 쓰이는 값 있는 행을 위로, 영값 묶음을 블록 맨 아래에 k-dim/k-faint로 |
| **H3 병기 2값** | 병기 줄은 값 2개까지(`익일 동일`, `현금·대용 반반`처럼 한 구절). 3개 이상이면 행으로 분리하거나 펼침으로 |
| **H4 행 리듬** | 본문 13px · 행 높이 32px · 블록 제목 위 여백 10px. 레일 블록당 6행 예산은 H1 적용 후 기준 |

## 4. 표 유형별 표준 열 세트

| 표 유형 | 기본 열(≤ 8) | 병기 줄 |
|---|---|---|
| 순위표 | 순위 · 종목 · 현재가 · 정렬지표 · 거래량 · 체결강도 · 연속일 · 시장 | 종목↓코드, 현재가↓전일대비·등락률, 거래량↓거래대금 |
| 투자자표 | 주체 · 매도 · 매수 · 순매수 · 비중 · 5일 누적 | 순매수↓수량, 주체↓연속일 |
| 거래원표 | 순위 · 창구 · 매도 · 매수 · 순매수 · 증감 · 비중 | 창구↓코드 |
| 보유표 | 종목 · 수량 · 평단 · 현재가 · 평가액 · 손익 · 비중 | 손익↓수익률, 종목↓코드·신용구분 |

### 6.2 마일스톤과 검수

사용자 규칙(10% 단위 스크린샷 검수)을 그대로 따른다: **60 · 70 · 80 · 90 · 100%** 통과 시점마다 전 보드 PDF를 발송하고 승인 후 다음 배치로 간다. 배치 경계와 마일스톤이 어긋나면 마일스톤이 우선이다(배치 중간이라도 발송).

### 6.3 배치 게이트 (매 배치 종료 시 전부 통과)

1. **원장** — 필드 원장 fail-closed 재집계, 행마다 보드 id·층·위치 근거.
2. **문구** — 설명문 0 · 영문 단위 0 · 내부어 0(스크립트 + 육안).
3. **정본** — canon 데이터셋 정합(삼성전자 150,850 · +1,850 · +1.24% 세계 등), 보드 내 합계 = 부분합.
4. **밀도** — §2.3 예산 위반 0(열·KPI·레일·높이 스크립트 검사).
5. **렌더** — 잘림·겹침 0, 상승 빨강/하락 파랑, 상태 표기에 색+문구.
6. **검수** — 마일스톤 PDF 사용자 승인.

### 6.4 앱 파리티 (병행 트랙, 별도 배치)

문법 7종은 각각 앱 계약 하나에 대응한다 — A/D: 셀 템플릿(주값·보조값), B: `column_priority` 표준 열, C: 표시 행 상한, E: 상태 밴드 필드, F: 접힘/펼침 토글 상태, G: 섹션 신설. Paper 배치가 끝난 문법부터 `integrated-card-surface` 계약에 반영하고 `verify-integrated-cards`로 검증한다.

### 6.5 리스크와 미결

- **높이 예산 초과** → 원칙상 펼침으로 내린다. 메인 보드를 1,120px 넘게 키우지 않는다.
- **세계관 확장** → 새로 등장하는 값은 canon 원장에 등록 후 사용(스팟 정합 재발 방지).
- **호가단위 100원** — 현재가 150,850이 15만원대 100원 단위 위반. 전 보드 가격 전환이라 본 계획과 분리, 사용자 결정 대기.
