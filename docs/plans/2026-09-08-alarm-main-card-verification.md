# 알람 메인 카드 구현 및 검증

## 구현 결과

알람 팝업에서 `대화창에서 카드 보기`와 `에이전트로 이동`을 선택할 수 있다. 대화창 경로는 알람 생성 시 사용자가 확정한 조회 operation과 인자로 새 대화를 열고 해당 카드 한 장을 표시한다. 에이전트 경로는 해당 알람을 선택한다.

채팅에서 알람을 만들 때 카드 후보를 먼저 제시하고 `이 알람에 맞는 카드는 … 맞나요?`라고 묻는다. 확인 버튼 또는 해당 대화의 유일한 대기 질문에 대한 명시적 긍정 답변으로 메인 카드를 저장한다. 카드 선택과 알람 활성화는 별도 단계다. 다른 카드를 요청하면 같은 초안의 후보를 교체한다.

확정된 카드가 없는 기존 알람에는 카드 이동을 비활성화하고 안내한다. 임의의 대체 카드를 표시하지 않는다. 조회 실패나 대화 전환 시 늦은 결과를 다른 대화에 표시하지 않는다.

## 검증 근거

- 모든 수정 후 앱 전체 단위 테스트: 3,813개 통과, 실패·건너뜀·TODO 0개.
- 작성과 별개 코드 검토: APPROVE, 남은 지적 0개. 변경 JavaScript 구문 검사와 Python Ruff·compileall 및 diff 검사 통과.
- 백엔드 후보 검증, 저장, 확인, API, MCP, 발화 이벤트 테스트: 131개 통과.
- 메인 프로세스 카드 조회 및 대화 경계 테스트: 마지막 수정 후 15개 통과.
- Electron 팝업 프로브: 일반 창과 400×600 좁은 창에서 버튼 표시, 입력 포커스 유지, 카드 미설정 안내 통과.
- Electron 전체 셸 프로브: 명시적 카드 확인 1회, 카드 조회 1회, 카드 한 장 표시, 기존 대화 카드 복원, 카드 전용 대화 재열기, 해당 에이전트 선택 통과.
- 통합 점검에서 발견한 카드 전용 대화의 이력 누락 및 기존 대화 카드 초기화 문제를 수정했다.
- 목록의 주기적 갱신은 실제 대화 ID가 변경된 경우에만 카드 렌더링을 무효화하도록 보완했다.

## 검증 범위와 현재 상태

Electron 프로브는 격리된 사용자 프로필과 명시적인 검증용 응답을 사용했다. 실제 시세 공급자 조회 및 실제 사용자 알람 발화는 이번 검증에 포함되지 않는다.

백엔드의 더 넓은 루틴 테스트에서는 코드 감시 sandbox 실행 실패 8건이 남았다. 대표 실패 1건은 변경하지 않은 원본 main에서도 같은 Python으로 재현했다. 나머지 7건은 같은 증상이지만 원본에서 각각 재현하지 않았다.

이 기록은 `codex/alarm-main-card`의 기능 검증 결과다. 이후 사용자 요청에 따라 커밋·푸시·main 병합 후 재검증을 진행한다. 실행 중 앱 재시작 및 실서비스 검증은 이 기록의 범위에 포함되지 않는다.

## 주요 파일

- `backend/athena_api/routines/main_card.py`: 카드 후보 및 저장 계약 검증.
- `backend/athena_api/api/routines.py`: 후보 교체와 사용자 확인 API.
- `app/lib/main/routine-main-card.js`: 저장된 카드 한 장 조회와 대화 범위 검사.
- `app/chat.js`: 카드 제안·확인과 알람 활성화 연결.
- `app/lib/sidebar.js`, `app/canvas.js`: 두 목적지 이동과 카드 전용 대화.
- `app/probe-routine-main-card.js`: 카드 확인·이동·복원 통합 프로브.
