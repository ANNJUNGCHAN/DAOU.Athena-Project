## 1. LLM 경로 구조 (가장 큰 레버)

### 1-1. `claude -p` CLI 스폰 폐기 — CARD-CLI-DROP ★핵심
AITS도 한때 **Athena와 동형**인 claude-cli 프로바이더(서브프로세스 스폰)를 메인 경로에
썼다가 완전히 걷어냈다. 사유 두 가지:
① `claude -p`는 **구조화 tool_calls 출력을 못 낸다** — tool_use 단일 트랜스포트 전환의 유일한 차단 요인
② 콜드 스폰 지연(관측 ~10.2s — 이후 재현 불가로 수치 자체는 폐기하고 실측치로 대체)
지금은 상시 HTTP API(litellm/ChatAnthropic)만 메인 경로이고, CLI 연결은 "문답 전용"으로
격리(`LocalCliChatModel.bind_tools`가 도구 바인딩을 명시적으로 거부).
- 근거: `src/core/settings/llm-connection.ts:45-49, 75-79` · `scripts/audit/sla-baseline.json` · `app/assist/providers/local_cli_chat.py:62`
- 실측: openai HTTP(1턴+도구1회) avg **3.656s** / max 3.797s vs claude-cli 순수완성 avg 5.672s

### 1-2. 상시 단일 백엔드 + session_id 대화 지속
LLM 호출 = 부팅 시 1회 스폰된 영속 FastAPI에 `POST /agent/chat` **1회 왕복**.
도구 호출 루프(LangGraph)는 그 프로세스 **내부**에서 전부 돈다 — LLM이 N개 도구를
불러도 Electron↔Python 왕복은 1회+스트림 구독뿐.
- 근거: `src/main/handlers/ai-chat-backend-agent.ts:225-259` (응답에 `tool_calls: number` 요약만)

### 1-3. tool_choice 강제 — 재시도 계열 제거 (CARD-TOOLUSE)
자유 텍스트 JSON 파싱은 thinking 혼입·형식 이탈로 재시도(=왕복 배증)가 구조적으로
발생 → 4개 스키마를 4개 도구로 선언하고 tool_choice를 전 경로에 강제해 실패 계열
자체를 소거. 실앱 검증 "재시도 0회로 1왕복 종결".
- 근거: `docs/js/data-unified.js:3885-3919` + 코드 확인됨

### 1-4. 프롬프트 캐싱 보존 — byte-identical 정적 시스템 프롬프트
시스템 프롬프트에 동적 값(종목명·시각·요청ID)을 **1바이트도** 보간하지 않는다 —
"프로바이더 프리픽스 캐싱은 1바이트만 달라져도 이득이 사라진다". 동적 값은 전부
user 메시지로. 회귀 검사 항목으로 명문화.
- 근거: `app/console/run_command/canvas_intent_prompts.py:21-25`
- Athena 점검 포인트: `live-prompt.js`가 질의마다 달라지는 값을 시스템 프롬프트에 넣는지 확인

### 1-5. 지연 도구 로딩 (LazyToolSurfaceSession)
턴 시작 시 LLM에는 `search_tools` 메타 도구 1개만 노출, 필요한 도구를 검색→로드로
그 턴에만 편입. TR 카탈로그 175종을 프롬프트에 인라인하지 않는 근거를 "**≈3.5k 토큰을
매 호출마다 지불**"이라고 계산해 남김.
- 근거: `app/assist/engine/tool_search_session.py:48-50` · `app/assist/ask_ai/tr_catalog.py:8-10`

### 1-6. 컨텍스트 예산 — AI_HISTORY_TURNS(기본 20턴) + 백엔드 단일 소재지 판정
- 근거: `src/core/settings/set-policy/general.ts:60` · `app/assist/ask_ai/policy.py(prepare_history)`

### 1-7. 총예산(Total Budget) SLA — "재시도는 실패 종류가 아니라 남은 예산으로 갈린다"
타임아웃(8s)을 재시도 루프 안에 두면 최악 대기가 8s×시도수로 **곱해지는** 버그를
ClassifyBudget(요청 시작 시 예산 1회 확정, 시도들이 나눠 씀)으로 구조 차단.
**타임아웃엔 재시도를 안 붙인다** — 타임아웃 걸린 호출은 p50의 5배 이상이라 재시도해도
또 걸릴 공산이 커 사용자 대기만 2배가 된다는 실측 근거.
- 근거: `app/console/run_command/canvas_intent_perf.py:8-34, 76-105`

## 2. 캐시·데이터 재사용

### 2-1. 시맨틱 2단 캐시 — L1 완전일치 + L2 정규형 ★핵심
"규칙 기반 전면 금지(모든 명령은 LLM 경유)" 원칙을 유지하면서 **캐시만 유일한 예외**.
- L1: 잡음 제거 후 원문 완전일치 (TTL 300s, 최대 500엔트리 FIFO)
- L2: **LLM이 이미 내린 판정**(intent·정렬된 종목코드·view)을 정규형 키로 재적재 —
  "삼전 차트"와 "삼성전자 차트 띄워"가 동의 표현이어도 2회차부터 LLM 무호출 적중.
  저장 시 종목명 뺀 잔여 토큰("차트")을 함께 저장, 조회 시 결정적 리졸버로 부분집합 검사만.
- 정당화 논리(이식 가치 높음): "**새 판단을 규칙이 대신하는 게 아니라, 이미 내린 LLM
  판정의 조회 인덱스**다" — Athena의 "셀렉터 랭킹 결정론" 원칙과도 충돌하지 않는 프레임.
- 근거: `app/console/run_command/canvas_intent_cache.py:43-49, 99-219` (코드 확인됨)

### 2-2. 화면/카드 선택을 LLM 왕복 없이 결정론적 BM25로
"어떤 화면을 띄울지"를 순수 인메모리 BM25(임베딩·모델호출·무작위성 0)로 판정,
색인은 `@lru_cache(maxsize=1)` 프로세스 싱글턴. **Athena CLAUDE.md §7의 "셀렉터 랭킹은
결정적·설명 가능" 원칙을 이미 코드로 구현한 사례** — Athena 셀렉터의 search/resolve
왕복을 줄일 직접 참고.
- 근거: `app/assist/tools/bm25_search.py` · `canvas_screen_search.py:143-146` — recall@5 88.2%→92.2% 실측

### 2-3. 참조 데이터 부팅 워밍업(hydrate) — 핫패스 백엔드 왕복 0
종목/업종/회원사 마스터·별칭 사전을 부팅 시(및 backend ready 전이마다) 통째로 메모리
미러에 적재. 읽기는 전부 동기 메모리, 쓰기는 낙관 갱신+fire-and-forget.
종목 검색은 전량 메모리 인덱스(부분일치+초성, 목표 <30ms). 마스터는 SQLite(WAL)에
일 1회 배치 동기화 — 카드 표시는 TR 재호출 없이 로컬 SELECT만.
- 근거: `src/common/cache-stock/alias-read-cache.ts:8-11` · `src/infra/storage/stock-search-index.ts:18-22`

### 2-4. 현재가 단기 TTL 캐시(QuoteCache) — 표시 전용
(모드+계좌+종목) 키, TTL 1초. 실시간 구독 중이면 캐시 우회(더 신선한 쪽 우선), 틱 수신
시 invalidate. **안전 불변식: 발주/검증 경로는 이 캐시를 절대 읽지 않는다** — Athena의
정보 정직성 원칙과 정합.
- 근거: `src/common/quote-cache/quote-cache.ts:17-19, 76-96`

### 2-5. 클라이언트 인스턴스 재사용 + 키움 토큰 선제 갱신
- KiwoomRestClient: (mode, tokenManager) 키 동일 시 재사용 — 조회 카드마다 새 생성 비용 제거 (`main-clients.ts:110-154`)
- TokenManager: 만료 **600초 전** 타이머 선제 갱신 + single-flight — 질의 경로에서 인증 대기 0 (`token-manager.ts:18, 96-109`)

### 2-6. R15 — 반복 왕복 횟수를 실측 기반으로 캡
카드 조회의 TR 페이지네이션이 1req/s 리밋과 곱해져 **~100초** 지연(Athena 차트 결함과
수치까지 유사) → 페이지 상한 기본 2(≈2초)·최대 10으로 캡. "반복 왕복 수 자체를 캡한다"
방법론 — Athena가 오늘 넣은 athena_call 트리밍과 동일 사상.
- 근거: `src/core/settings/set-policy/general.ts:44-46`

## 4. 운영 규율 (지연이 조용히 나빠지는 것을 막는 장치)

- **SLA 기준선 CI 게이트**: 실측(avg/max/hardMax)을 JSON으로 커밋하고, FE 타임아웃
  clamp와 최근 실측을 자동 대조(`npm run audit:sla-baseline`). "추정 금지 — 먼저 잰다"
  — 근거 없던 수치(콜드스폰 10.2s)는 재현 불가로 **폐기**하고 실측으로 교체한 이력까지 남김.
- **레이어드 타임아웃**: 클라이언트 안전망 = 백엔드 자체 상한 + 고정 버퍼 60s — 정상
  상황에선 항상 백엔드가 먼저 원인 있는 에러로 응답.
- **[perf] 구간 마커**: 명령→판정, 패널 개설→첫 데이터를 별도 로그 포인트로 상시 계측.
- **레이트리미터**: api-id별 버킷 + high/low 우선순위 큐 + 인터랙티브 전용 버스트로
  "사용자 단발 조회가 백그라운드에 밀려 ~3초 지연" 실측 문제 해결. ⚠ Athena §7
  "리미터는 하나" 원칙과 **긴장** — 버킷을 쪼개지 않고 `acquire(priority)` 개념만
  가져오는 절충 가능(Athena엔 이미 headroom 양보가 있음).
- **stdout 핸드셰이크**: `READY port=..` 정규식으로 폴링 없이 즉시 관측, 마스터 동기화
  완료도 별도 신호(완료가 수백ms~45s+로 진동한다는 실측 때문에 이벤트화).
- **부팅 스태거**: 마스터 동기화를 2.5s 늦게 시작 — 사용자 첫 조회가 리미터 큐 앞자리.

## 5. 반면교사 (그대로 배끼면 안 되는 것)

1. **결정론 AST 파서 fastpath를 만들었다가 걷어냄**: 발주/조회/창제어를 LLM 없이 즉시
   처리하는 CommandParser(+전용 지연 계측기)가 있었으나, "채팅창은 전량 자연어(에이전트
   단일 경로)" 전환으로 실 라우팅에서 제거되고 회귀 오라클로만 남음. **Athena가 "정형
   요청 지름길"(어제 제안 1번)로 가려는 방향과 정반대의 실제 사례** — 다만 AITS도
   슬래시 명령의 `kind:'local'` 결정론 처리와 시맨틱 캐시는 남겼다. 교훈: "지름길
   전면화"가 아니라 **"LLM 판정의 재사용(캐시)" + "명시적 명령(슬래시)만 로컬"**이
   그들이 수렴한 균형점.
2. **경량 모델 전환 실패 사례**: 분류를 gpt-5-mini로 바꾸려던 A/B — golden 24건 실왕복
   48회 측정 결과 정확도 75.0%→**20.8%** 폭락, 지연도 악화(p50 1.5s→8.0s). 채택 안 함.
   "가벼운 모델 이름"만 믿으면 정확도·지연 둘 다 잃는다 — **모델 교체는 실측 A/B 게이트 필수**.
3. **로컬 모델 ≠ 빠름**: ollama 분류 실측 p50 28.8s·max 57.2s — 로컬 경유가 오히려
   훨씬 느릴 수 있다.
4. **문서상 원칙 ≠ 구현**: "모델 자동 라우팅(smartroute)"·병렬 서브에이전트 조사원은
   devplan 명문화만 있고 미착수/부분 구현 — 인용 시 코드-문서 구분 필요.
