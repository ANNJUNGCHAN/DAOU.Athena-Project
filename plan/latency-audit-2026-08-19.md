## 1. 비판 — 어디가 왜 느린가 (실측 기반)

### 1.1 질의: 주범은 백엔드가 아니라 왕복 구조다
- **낭비 턴 6회가 그대로 방치돼 있었다.** 프롬프트에 "숫자 변환·정렬" 지시가 이미 있는데도 모델이 Bash를 3회 시도했다
  — 전부 거부됐고 왕복 시간만 소모. 지시가 있어도 도구가 보이면 쓰려 든다: **도구를 보이게 둔 것 자체가 설계 결함이다**
  (`claude-runner.js`가 빌트인 도구 표면을 제한하지 않음).
- **4단계 왕복이 구조적 하한을 만든다.** 툴 하나당 모델 판단 왕복이 끼므로, 4툴 계약을 지키는 한 감사 간격 합에는
  모델 사고 시간이 최소 3회 곱해진다. "4툴 합 ≤5초" 목표는 3분해(US-002) 결과에 따라 재협상 대상.

### 1.2 부팅: 폴링 12초 상한은 설계가 아니라 방치다
- lifespan이 계정 토큰 발급(키움 왕복)을 **동기로 물고** 있어 manifest 200이 그만큼 늦다 — 분해 계측(US-001) 후 판정.

### 1.3 테스트: 164초 순차 실행

## 2. W2 판정 — 실측이 두 번 말했다 (2026-08-19)

- **W2a(무비용)**: `claude --help` — `--tools <tools...>` = 빌트인 셋 매니페스트 제어, `""`는 전부 비활성.
  `--disallowedTools`는 거부 계층. → 1차 결정: `--tools ""`.
- **W2b(E2E) — 1차 결정 기각**: `--tools ""` 적용 E2E 2회에서 **툴 사용 0건·캔버스 0건** — 모델 자백
  *"세션에 athena_* 툴이 없다"*. 이 구성에서 **MCP 툴은 지연 로딩**이라 ToolSearch로 로드해야 하는데
  로더까지 제거된 것. (`PROBE-KIWOOM-CHART-run1/2.json`)
- **기준선 재해석(비판의 정정)**: 낭비 6턴 중 ToolSearch 2회는 낭비가 아니라 **키움 툴 로딩의 필수 경로**였다.
  진짜 낭비는 Bash 3·Grep 1 = **4턴**. §1.1의 비판 강도는 유지하되 수치를 정정한다.
- **2차 결정**: `--tools "ToolSearch"` — 로더만 남기고 Bash/Grep/기타 빌트인 제거. run3로 검증.
- **W2b(E2E) — 2차 결정도 기각 (run3~5, 실측이 세 번째로 말했다)**:
  - run3 (96.3초·31턴): describe 생략 규칙과 겹쳐 인자 추측→실패→재resolve 루프 (resolve×4·call×3).
    describe 생략 규칙은 즉시 철회 — 필수 인자 목록이 describe에만 있다.
  - run4 (104.4초·29턴): describe 복원 후에도 중간 ToolSearch×3 (render_canvas 사냥) + 성공 사이클
    재반복. 감사 로그 플래그는 정상인데 총시간이 기준선보다 24~32초 나쁨.
  - run5 (60.3초·20턴): 선로딩 지시 실험 — ToolSearch 사냥은 여전(×3), **render_canvas 미호출로
    카드 0건 = 기능 실패**. (`PROBE-KIWOOM-CHART-run3/4/5.json`)
  - 공통 원인: 이 CLI 구성에서 MCP 툴은 **ToolSearch 경유 지연 로딩**인데, `--tools`로 빌트인을
    깎으면 그 로딩 경로가 불안정해져(툴 탐색 실패·재시도) 아낀 4턴보다 훨씬 큰 비용이 든다.
- **최종 결정 (철회)**: `--tools` 플래그 자체를 제거하고 기준선 매니페스트로 복귀.
  기준선의 Bash 3·Grep 1 낭비 4턴(~10초)은 깨진 지연 로딩(+24~32초 또는 렌더 실패)보다 싸다.
  §1.1의 "도구를 보이게 둔 것 자체가 설계 결함" 비판은 **기각으로 정정한다** — 표면 축소는 이
  구성에서 순손실이었고, 낭비 턴 억제는 프롬프트 규율(재조회 금지·첫 카드 우선)로만 한다.
  재도입하려면 E2E 재실측이 선행 조건이다 (`app/lib/main/claude-runner.js` 주석에 명문화).
- auto_execute 에스컬레이션: 불발동 유지 (매니페스트 제어 자체는 동작 확인 — 범위 선택의 문제였다).
