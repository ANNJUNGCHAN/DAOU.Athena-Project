# 차트 렌즈 계약 스펙 (1판)

> 기준일: 2026-08-18 · 성격: **계약 스펙**(설계 확정 문서). 실측 근거는
> `plan/chart-lens-aits-survey.md`. spec §9(`plan/kiwoom-common-screen-spec.md` line 260-267)의
> "시계열(차트) 렌즈는 저작 상태를 갖는다" 결정을 구체화한다.
> 렌즈 정의: `AT-CV-002`(시계열 렌즈, 2차 예약) 위에 얹는 저작 계층 — 이 문서가 다루는 것은
> AT-CV-002 자체가 아니라 그 위의 저작 계층 계약이다. AT-CV-002 설계 착수는 후속 라운드.

## 0. 결정 기록

**결정 1 — 실측 범위 대체 (2026-08-18, 사용자 판정)**
원 계획은 "토스증권 WTS 실측"이었다. 사용자가 이를 **AITS 차트 실측으로 대체**하도록 판정했다.
근거(사용자 발화 그대로): *"AITS가 토스증권 WTS를 따라한 것이므로 AITS 차트 기능과 동일하면 됨."*
→ 실측 소스는 WTS가 아니라 `C:\Projects\DAOU.AITradingSystem`(AITS)의 실 컴포넌트 소스와 화면
등록부다(`chart-lens-aits-survey.md` §0).

**결정 2 — 범위 게이트 (2026-08-18, 사용자 판정)**
**차트 작도(드로잉) 포함 AITS 차트 기능 전부**를 계약 1판의 대상으로 한다. 부분 채택(예: 드로잉
제외)은 하지 않는다.

**선행 결정 (2026-08-17, `kiwoom-common-screen-spec.md` §9 인용)** — 이 스펙이 상속하는 상위 결정:
> "시계열(차트) 렌즈는 저작 상태를 갖는다(사용자 결정). 보조지표는 질의 기반("볼린저 얹어줘")으로도
> **수동 드로잉으로도** 조작 가능해야 하며, 차트 기능은 **토스증권 WTS와 동등**을 목표로 한다. 즉
> 렌즈는 "같은 데이터의 다른 표현"을 넘어 상호작용·주석(영속) 상태를 보유할 수 있다."

이 세 결정을 합치면: "WTS 동등" 목표는 유지하되(선행 결정), 실측 방법은 AITS로 대체하고(결정 1),
AITS가 실제로 구현한 전부(드로잉 포함)를 계약 대상으로 삼는다(결정 2). AITS가 WTS를 따라 만든
것이므로 두 목표가 충돌하지 않는다는 것이 사용자의 판단이다 — 이 스펙은 그 판단을 그대로 채택한다.

## 1. 렌즈 계약 정의

```
CompoundCard(charts)          ← 완전성 계층(감사 §2) — 206개 TR을 전부 무손실로 배정
      │
      ▼
시계열 렌즈 (AT-CV-002, 2차 예약)   ← 표현 계층(spec §9) — "같은 데이터를 시계열로 그린다"
      │
      ▼
저작 계층 (본 스펙)              ← 이 문서 — 시계열 렌즈 위에 상호작용·주석 상태를 얹는다
```

- **CompoundCard(charts)**는 감사 §5.1이 이미 확정한 원장이다: "봉차트 데이터(일/분/주/월/년/틱)
  = CompoundCard(charts 12) + 시계열 렌즈(2차, AT-CV-002), 데이터 무손실, 시각화는 표현 계층." 이
  스펙은 이 배정을 재론하지 않는다.
- **시계열 렌즈**는 "무엇을 그리는가"(캔들/OHLC/거래량 시계열)를 정의한다. 아직 미착수(2차 예약).
- **저작 계층**은 "그 위에 사용자가 무엇을 더할 수 있는가"(지표·드로잉·차트형식·매물대, 그리고
  그것들의 저장·복원)를 정의한다 — **이것이 이 스펙의 본문**이다.

저작 계층은 시계열 렌즈에 종속된다. 시계열 렌즈 없이 저작 계층은 존재할 수 없다(그릴 캔버스가
없으므로) — 따라서 AT-CV-002 착수 전에는 이 스펙이 실행 가능한 상태가 아니다. 이 문서는 AT-CV-002
설계에 앞서 계약 형태를 고정해 두는 것이 목적이다(§7 미해결에 재확인).

## 2. 진입 이중화 — 질의 기반 + 수동 드로잉

선행 결정(§0)이 요구한 이중 진입을 AITS 실측(survey §3.5)이 그대로 뒷받침한다:

| 진입 방식 | AITS 대응 | Athena 계약 |
|---|---|---|
| 질의 기반 ("볼린저 얹어줘") | 없음 — AITS 지표 패널은 UI 토글 클릭만 지원, 자연어 지표 지정 없음(실측: `ChartIndicatorPanel.svelte` 전체에 질의 파서 없음) | **신규 결정** — 대화 창(커맨드바) 자연어 → 백엔드 셀렉터가 지표 키(§4 인벤토리의 35종 표준 이름)로 해석 → 렌즈에 반영. 파서·매핑 설계는 후속 라운드(§7) |
| 수동 드로잉 | 있음 — 7종 도구(추세선·수평선·피보나치·십자선·광선·사각형·타원), 팔레트·선굵기·선종류·불투명도 편집(survey §3.5-3.6) | **AITS 그대로 계승** — 7종 도구·스타일 편집기를 1판 계약에 포함(결정 2) |

질의 기반 지정은 AITS에 선례가 없는 Athena 고유 확장이다 — "AITS 실측으로 대체"(결정 1)는 드로잉
같은 이미 구현된 기능의 실측 대체이지, 질의 기반 지정처럼 선행 결정이 이미 요구한 신규 기능까지
축소하는 것은 아니다.

## 3. 저작 상태 저장·복원 계약 (필수)

survey §4가 실측한 AITS 현황: **드로잉만 영속되고, 지표·매물대·차트형식은 영속되지 않는다**(세션마다
기본값으로 리셋). 선행 결정("저작 상태를 보유할 수 있다")은 드로잉에 국한하지 않는다 — 이 스펙은
AITS의 부분 영속을 그대로 승계하지 않고 **저작 상태 전체를 종목×주기 키로 영속하는 것으로 확장
결정**한다.

### 3.1 무엇을 영속하는가 — 저작 상태 4종

| 저작 상태 | AITS 현황(survey §4) | Athena 계약 |
|---|---|---|
| 드로잉(7종 스냅샷) | 영속됨 | 계승 |
| 보조지표 on/off·파라미터·색(35종) | 영속 안 됨 | **신규 영속 대상으로 승격** |
| 차트형식(캔들/바/라인/영역) | 영속 안 됨(항상 캔들로 시작) | **신규 영속 대상으로 승격** |
| 매물대 on/off | 영속 안 됨 | **신규 영속 대상으로 승격** |

주기(일/주/월/…)·수정주가 토글·줌 뷰포트는 저작 상태가 **아니다**(조회 파라미터·휘발성 표시
상태) — 영속 대상에서 제외한다. AITS도 이를 영속하지 않는다(survey §4 표).

### 3.2 스키마 초안

**무엇을**: 종목×주기 1쌍의 저작 상태 스냅샷 1개.
**키**: `{symbol}×{period}` — AITS의 `chart.drawings.${symbol}.${period}` 키 패턴을 확장 계승한다.
정확한 키 문자열·저장소 API 이름은 백엔드 구현 라운드에서 확정한다(아래는 계약 *형태*만 고정).

```
authoring_state[symbol][period] = {
  schemaVersion: number,        // AITS에 없던 필드 — 신규 필수(survey §5-2가 지적한 갭 보완)
  drawings: {
    lines: Drawing[],           // 추세선
    hlines: Drawing[],          // 수평선
    fibos: Drawing[],           // 피보나치
    crosshairs: Drawing[],      // 십자선
    rays: Drawing[],            // 광선
    rects: Drawing[],           // 사각형
    ellipses: Drawing[],        // 타원
  },
  indicators: {
    [indicatorKey]: { on: boolean, params?: Record<string, number>, colors?: string[] }
    // indicatorKey는 §4 인벤토리의 35종 표준 키(예: 'ma','boll','rsi',...,'mfi')
  },
  chartForm: ChartFormKind,     // 'candle'|'bar'|'line'|'area'(1판 선택 가능 4종, §4)
  volumeProfileOn: boolean,
}
```

- `drawings`의 7개 배열 구조는 AITS `chart-drawing-store-io.ts`의 `ChartDrawingsSnapshot`을
  그대로 계승한다(survey §4.1) — 재발명하지 않는다.
- `schemaVersion`은 AITS에 없던 필드다(survey §5-2 실측 불가 항목) — 이 스펙에서 **신규 필수**로
  못박는다. 향후 도구 종류가 늘거나 줄 때(예: vline 부활 여부, §4) 마이그레이션 판정의 유일한
  근거가 된다.
- 백엔드 저장소(SQLite 계속 사용 vs 다른 저장소)는 후속 라운드 소관(§7) — 이 스펙은 스키마 *형태*만
  고정한다.

### 3.3 저장·복원 동작 계약

- **저장 시점**: 저작 상태가 실제로 바뀌는 시점마다 즉시(디바운스 없음) — AITS 관례(survey §4.1)
  그대로 계승. 드로잉 확정 클릭, 지표 토글, 차트형식 전환, 매물대 토글 각각이 트리거.
- **복원 시점**: 카드 마운트·종목/주기 전환 시. 저장값 없음(신규 종목×주기 쌍)이면 빈 상태로
  degrade — 오류가 아니다.
- **레이스 가드**: 종목/주기 빠른 전환 시 응답이 요청 순서와 다르게 도착할 수 있다 — 응답 도착
  시점의 "현재 대상 키"와 요청 키가 일치할 때만 반영한다(AITS `chart-drawing-store-io.ts:86-97`
  패턴 계승, survey §4.1).
- **실패 시 표시**(soul.md §8 정보 정직성 적용, §6 참조): "저장값 없음"(신규)과 "조회 실패"(네트워크
  오류 등)는 다른 상태다. AITS는 이 둘을 구분하지 않는다(둘 다 빈 상태로 degrade) — Athena는
  **구분해서 실패를 감춘 빈 상태로 오인하지 않게 한다**. 구체적 UI 표시 방식은 후속 라운드.

## 4. 기능 인벤토리 — 카드/렌즈/저작 계층 배속

survey §2~§3 실측 기반. "계약 1판 = AITS 전부"(결정 2)이므로 아래 전 기능이 포함 대상이다 —
제외 항목은 없다.

| 기능 | 실측 수량 | 배속 | 저작 상태? |
|---|---|---|---|
| 주기(일·주·월·년·분·틱) | 6 + 분/틱 세분 | 시계열 렌즈(AT-CV-002) 조회 파라미터 | 아니오 |
| 차트형식(선택 가능) | 4종(캔들·바·라인·영역) | 저작 계층 | **예** |
| 차트형식(정의만, 미노출) | 8종(하이킨아시·렝코·카기·P&F·삼선전환·투명캔들·베이스라인·역시계곡선) | 계약 밖(§7 후속) | — |
| 보조지표 | 35종(레거시 13 + 확장 22) | 저작 계층(오버레이) | **예** |
| 매물대 | 1(토글) | 저작 계층(오버레이, 지표 목록과 별도 UI 요소) | **예** |
| 드로잉 도구 | 7종(추세선·수평선·피보나치·십자선·광선·사각형·타원) | 저작 계층(핵심) | **예** |
| 드로잉 스타일 편집 | 색·선굵기·선종류·불투명도 | 저작 계층(드로잉의 부속 속성) | 예(드로잉 객체 안에 포함) |
| 수정주가 토글 | 1 | 시계열 렌즈 조회 파라미터 | 아니오 |
| 줌·팬 | zoomIn/Out·pan·reset | 렌즈 표시 상태(휘발성) | 아니오 |
| 진행봉 롤오버(실시간) | updateLastCandle·rollOverCandle | 렌즈 표시 로직(구독 갱신) | 아니오 |
| 봉당 상세(표) | -DETAIL 화면 4장 | §7 후속 — Athena에서 별도 화면 유지 vs 카드 내 보조 표현 흡수 미정 | — |
| 투자자·기관 흐름/표 | -INVESTOR, -INVESTOR-TABLE 2장 | CompoundCard(charts) 원장 그대로(실 차트 미적용 자산, survey §2.4) — 저작 계층 적용 범위 밖 | 아니오 |

카드 종류는 늘지 않는다: 35종 지표 + 7종 드로잉 + 4종 차트형식 + 매물대 전부가 **CompoundCard 1종
위 시계열 렌즈+저작 계층의 파라미터**로 흡수된다. §6에서 재확인.

## 5. 사용자 결정 3줄 요약

1. 실측 소스를 WTS에서 **AITS 실 구현(코드)**으로 대체 — AITS가 WTS를 따라 만들었다는 판단 근거.
2. 계약 1판 범위는 **드로잉 포함 AITS 차트 기능 전부** — 부분 채택 없음.
3. 저작 상태는 AITS의 "드로잉만 영속"을 넘어 **지표·차트형식·매물대까지 종목×주기 키로 영속**하도록
   확장 — AITS 갭을 그대로 승계하지 않는다.

## 6. 불변 제약과의 관계

- **카드 6종/12종 불늘림** — §4가 보이듯 신규 카드 종류 0. 전부 CompoundCard(charts) 위 파라미터.
  감사 §5의 "카드 최소화 판정: 신규 카드 0종" 원칙과 정합.
- **데이터 무손실** — 저작 상태 스키마(§3.2)는 AITS가 실제로 구현한 상태 전부를 담는다(드로잉
  7종·지표 35종·차트형식 4종·매물대). 축약 없음.
- **정보 정직성(soul.md §8)** — §3.3의 "저장값 없음 vs 조회 실패 구분"이 이 원칙의 직접 적용.
- **두 창 원칙** — 드로잉 툴바·팔레트·지표 패널은 전부 캔버스 창의 카드 내부 UI다(AITS도 카드
  내부, survey §3.5 "전체화면(큰 창)에서만"). 새 창을 열지 않는다 — AITS의 "전체화면"은 별도
  OS 창이 아니라 카드 자체의 확장 상태(큰 카드)로 해석한다.
- **리퀴드 글래스 규범(ui/liquid-glass.md)과의 긴장** — 드로잉 팔레트는 사용자가 자유 HEX를
  고르는 기능이다("액센트 색 없음" 원칙과 표면적으로 충돌). 판정: 드로잉 선·채움 색은 **UI 액센트가
  아니라 사용자 주석 데이터**(캔들 상승/하락 색과 같은 급의 "정보 색")로 분류한다 — 규범이 금지하는
  것은 장식용 브랜드 액센트이지 사용자가 그은 선의 색이 아니다. 이 분류의 시각 스펙(팔레트 UI
  자체가 유리 표면 규범을 지키는 방식)은 후속 디자인 라운드 소관.

## 8. 용어 — GLOSSARY 등록 필요 목록

이 스펙에서 새로 쓴 용어. `GLOSSARY.md`는 직접 편집하지 않는다(작업 원칙) — 등록은 별도 작업.

  지표·드로잉·차트형식·매물대 선택의 총칭. "저작 상태"가 아닌 "표시 상태"(줌·팬 등, §3.1)와
  구분해야 한다.
- **저작 계층**(authoring layer) — 시계열 렌즈와 별개 층위. §1 다이어그램 참조.

  GLOSSARY 본문에 정의 항목이 없다(확인: `GLOSSARY.md` 전체에 "렌즈" 1회만 등장, 정의 섹션 없음).
