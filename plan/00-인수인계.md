## 1. ★ 작업 흐름이 **둘**이다 — 먼저 알아야 할 것

이 저장소에는 **서로 모르는 두 갈래**가 동시에 진행됐다. 충돌 지점이 있다.

| | **갈래 A — MCP·셸** (이 세션) | **갈래 B — 뇌·화면체계** (별도) |
|---|---|---|
| 계획 문서 | `mcp-실행계획.md`, `감시에이전트-실행계획.md` | [`investment-brain-architecture.md`](investment-brain-architecture.md), [`kiwoom-common-screen-brief.md`](kiwoom-common-screen-brief.md) |
| 코드 | `backend/athena_mcp/`, `app/`, `spike/` | `backend/athena_api/brain/`, `selector/`, `llm_tools.py` |
| 다루는 것 | 외부 MCP 서버 연결, 뉴스·공시, Electron 두 창 | LadybugDB 그래프 투영, 키움 TR 301개 라우팅 |

### 충돌 위험 3건 — 반드시 조율하라

**① "공통 캔버스" 개념이 양쪽에 따로 있다.**
갈래 A는 캔버스 16종(TR 12 + 신규 4)으로 접는다. 갈래 B는 **301개 라우팅 매핑을 "common canvas"로 렌더**한다고 쓴다.
같은 단어인데 스케일이 다르다. **어느 쪽이 상위 개념인지 정해야 한다.** 안 정하면 렌더러가 둘로 갈라진다.

**② `kiwoom-common-screen-brief.md`가 *"do not create a parallel replacement application"* 이라고 명시한다.**
그런데 이 세션이 `app/`에 Electron 앱을 새로 만들었다. 변명은 있다 — 저장소에 프론트엔드 코드가 **0줄**이었고 `app/`은 `ui/*.md` 설계 문서를 그대로 구현한 것이다. **하지만 갈래 B가 별도 UI를 상정하고 있었다면 지금 합쳐야 한다.**

**③ 기존 테스트 22개가 깨져 있다.**
전체 스위트 `22 failed, 403 passed`. 전부 `backend/athena_api/tests/unit/test_selector_eval.py` — **갈래 B의 진행 중 작업**이고 `athena_mcp`와 무관하다(`--ignore=tests/mcp`로 돌려도 동일). 갈래 A가 만든 게 아니다.

## 5. ★ 함정 목록 — 같은 곳에 두 번 빠지지 마라

### 개발 환경

**① 한글이 깨져 보이면 파일부터 확인하라.**
이 환경은 콘솔 코드페이지가 **cp949**다. `print()` 결과를 셸로 리다이렉트하면 한글이 깨진다.
이 세션에서 **세 번** 이 함정에 걸렸고, 한 번은 *"pykrx-mcp가 한글을 손상시킨다"* 는 **존재하지 않는 결함을 보고할 뻔했다.**
→ 반드시 `Path.write_text(json.dumps(..., ensure_ascii=False), encoding="utf-8")`로 저장하고 **파일을 열어** 확인하라.
실제로 한글이 깨지는 서버는 `@drfirst/korea-stock-mcp` **하나뿐**이다(재현 확인, 원인 미규명).

**② `require.main === module`은 Electron에서 항상 false다.**
`npm start`가 창을 안 띄우고 조용히 멈춘다. 자체 검증 스크립트는 `main.js`를 직접 require해서 이 경로를 안 타므로 **전 구간 통과로 보인다.**
→ `app/main.js`는 `ATHENA_NO_AUTOSTART` 환경변수로 교체했다. 건드리지 마라.

**③ 스크린샷 캡처가 간헐 실패한다.**
이 데스크톱을 다른 프로세스와 공유 중이라 `CopyFromScreen`이 엉뚱한 창을 찍는다.
→ `webContents.capturePage()`(렌더러 레벨)를 **주 증거**로, OS 합성 캡처는 보조로.

### MCP 연동

**④ `serverInfo.name`을 네임스페이스 키로 쓰지 마라.**
`pykrx-mcp`·`@drfirst/korea-stock-mcp`·`jjlabsio` **셋 다 `korea-stock-mcp`류로 보고했다.** 반드시 **사용자 별칭**을 키로.

**⑤ `serverInfo.version`을 믿지 마라.**
`pykrx-mcp`는 자기 버전이 아니라 **mcp SDK 버전(1.28.1)** 을 보고한다. `korean-dart-mcp`는 npm 최신(0.10.1)과 실행 버전(0.9.2)이 다르다.

**⑥ DART `corp_code`는 숫자로 온다.**
`126380`(정상은 `"00126380"`). 하위 호출은 `minLength:8` **문자열**을 요구한다. `str(x).zfill(8)` 없으면 `MCP error -32602`로 즉시 실패.

**⑦ `korean-dart-mcp`의 `truncate_at` 기본값은 100,000자다.**
삼성전자 사업보고서는 마크다운 636,059자 — **84%가 잘린다.** 명시적으로 키워라.

**⑧ 당일 접수 공시는 본문 조회가 실패한다.**
"대용량이라 실패"가 아니라 **"DART 문서저장소에 원문 zip이 아직 없어서"** 다. DART가 `{"status":"014"}` XML을 주는데 서버가 검증 없이 unzip하다 터진다.

### CLI

**⑨ `--setting-sources`는 반드시 빈 문자열이어야 한다.**
```bash
claude -p "..." --setting-sources ""      # 훅 0개 ✅
claude -p "..." --setting-sources "user"  # 훅 6개 ❌ 완화책 무력화
```
`"user"`처럼 값을 하나라도 주면 대조군과 **완전히 동일하게** 전부 로드된다.

**⑩ 헤드리스는 MCP 서버를 트러스트 확인 없이 시작한다.**
`npx -y <패키지>` = 임의 코드 실행이 무확인으로 벌어진다. **툴 호출**은 권한 게이트로 막히지만 **서버 시작**은 안 막힌다.
→ Athena의 `consent.py`가 이걸 막는다. 우회하지 마라.

### 보안

**⑪ sanitize한 문자열을 `innerHTML`에 넣지 마라.**
스트림 어댑터는 `<b>`를 스트립하고 엔티티를 언이스케이프한다. 그 결과물을 `innerHTML`로 재해석하면 **저장형 XSS**가 된다.
→ `app/`은 전부 `textContent`/DOM 노드로 렌더한다. 현재 `innerHTML` 문자열 삽입 0건. 유지하라.

**⑫ 감사 로그에 인자·응답 본문을 남기지 마라.** 계좌 정보가 흐른다.

Electron 최신 검증에서 확장 모션은 `p50=66.7ms`, `p95=116.7ms`, `max=116.7ms`였다. 머신 부하와 실행별 편차가 크지만, 기존 인수인계에 적힌 `p95=54ms`보다 나쁜 실제 측정치이므로 **프레임 최적화 우선순위는 유지가 아니라 상향**한다. 수축은 `p50=16.7ms`, `p95=16.8ms`로 안정적이었다.

### 비밀값 주의

KRX 인증 대조군 스크립트가 최초에는 `headers_sent`에 실제 `AUTH_KEY`를 그대로 기록했다. `spike/krx-probe/step1_auth_probe.py`를 수정해 실키는 `<redacted-valid-key>`로 저장하도록 바꿨고 현재 캡처도 마스킹했다. 다만 해당 원문이 포함된 과거 커밋이 원격에 올라간 이력이 있으므로 **KRX 키는 폐기·재발급하는 것이 안전하다.** 히스토리 강제 재작성은 공동 작업에 영향을 주는 파괴적 작업이라 이번 커밋에서는 수행하지 않았다.
