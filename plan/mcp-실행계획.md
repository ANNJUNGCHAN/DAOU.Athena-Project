## 1. 녹취가 요구하는 것 — 4갈래

| # | 요구 | 성격 | 선행조건 |
|---|---|---|---|
| **R1** | 부팅 시 대화 창만. 점 → 캔버스 창 확장 / 다시 점으로 수축 | 모션·창 관리 | Electron 셸 |
| **R2** | 투자정보(뉴스·공시·리서치)용 **범용 캔버스 최소 세트** | 데이터 설계 + UI | MCP 데이터 형상 확정 |
| **R3** | 자연어 → 그 자리에서 창 생성 → **저장** → 내 캔버스가 됨 | 코드 생성 + 샌드박스 | R2 계약 확정 |

단 R4만 하면 화면에 아무것도 안 나온다. R1(셸)과 **병렬**로 가야 한다.

## 2. 핵심 결정 — Athena는 MCP **게이트웨이**다

### 문제

`soul.md` §1: *"AI는 로컬 CLI(Claude Code / Codex / Gemini CLI)를 제어해서 동작한다. 자체 API 키를 쓰지 않는다."*
그러면 MCP 툴을 **누가** 부르는가? CLI가 부른다. 그런데 캔버스를 그리려면 **Athena가 그 결과의 구조화된 JSON을 봐야 한다.**

### 후보

| 안 | 방식 | 장점 | 치명적 약점 |
|---|---|---|---|
| **A · CLI 위임** | Athena가 `.mcp.json`을 써주고 `claude -p --output-format stream-json`의 `tool_result` 블록을 파싱 | 프로토콜 코드 0줄 | 결과가 텍스트 블록(대개 문자열화 JSON). 25k 토큰 상한. 2분 후 자동 백그라운드. **스트림 스키마에 공식 명세 없음**(anthropics/claude-code#24612). Claude Code 전용 — Codex/Gemini는 형식이 다름. **조용한 감시자가 LLM 토큰을 태워야 함** |
| **B · 게이트웨이** ✅ | Athena가 MCP **클라이언트**로 모든 등록 서버에 붙고, 집계한 툴을 **단일 MCP 서버**로 CLI에 재노출 | 네이티브 `CallToolResult`(`structuredContent` 포함)를 직접 봄. **CLI 종류와 무관**(전부 MCP를 말함). 감시자가 LLM 없이 툴 직접 호출 → 토큰 0 | 프로토콜 작업 실물. 네임스페이스·취소·진행토큰 리맵 필요 |

### 결정: **B**

근거는 녹취 자신에 있다.

> *"MCP도 기능을 하고 키움 레스트 API도 기능을 하는"*
> *"레스트 API가 호출되면 또 레스트 API를 호출하는 게 MCP 서버라고도 할 수 있지"*

사용자는 이미 **"키움 백엔드도 MCP 서버다"** 쪽으로 추론하고 있다. 이걸 그대로 받으면 통합 경로가 둘에서 하나로 접힌다.

```
        Claude Code CLI  (MCP 서버 딱 하나만 붙는다)
                 │
                 ▼
     ┌───────────────────────────┐
     │   Athena MCP Gateway      │  backend/athena_mcp/
     │  (server + client 겸업)   │
     ├───────────────────────────┤
     │ kiwoom__ka10001 …         │ ← athena_api 래핑
     │ naver-news__search_news   │ ← 사용자 등록 MCP
     │ dart__get_disclosure      │ ← 사용자 등록 MCP
     │ athena__render_canvas     │ ← ★ 캔버스도 툴이다
     │ athena__save_canvas       │
     └───────────┬───────────────┘
                 ▼  구조화 결과 + 캔버스 지시
          Electron (대화 창 / 캔버스 창)
```

### 이 결정이 공짜로 푸는 것들

1. **R1의 점→확장 트리거가 정해진다.** CLI가 `athena__render_canvas`를 부르면 캔버스 창이 펴지고, 안 부르면 안 펴진다.
   → *"오늘 날씨 어때?"* = 툴 호출 없음 = 점 그대로. 녹취 요구가 **메커니즘 하나로** 성립한다.
2. **캔버스 선택이 AI의 명시적 판단이 된다.** 추측 라우팅이 아니라 툴 인자다. 실패하면 로그에 남는다.
3. **CLI 교체가 설정 한 줄이 된다.** Codex/Gemini도 MCP를 말한다.
4. **조용한 감시자**(soul.md §6)가 LLM을 안 거치고 툴만 폴링한다.

### 등록 UX — 클로드 데스크탑 패리티는 사실상 공짜

조사 결과: `claude_desktop_config.json`의 스키마는 `{"mcpServers": {"이름": {"command", "args", "env"}}}` **그게 전부다**(stdio 전용). 이 블록은 Claude Code `.mcp.json`에 **무수정으로 유효**하다.
→ **"클로드 데스크탑 설정 스니펫을 그대로 붙여넣기"가 Athena 등록 UI의 1급 입력 경로**가 된다. 녹취의 "동일한 절차" 요구를 문자 그대로 만족.

원격 서버(Pulitzer 등)는 Streamable HTTP + OAuth 2.1 — **2단계로 미룬다.** 1단계는 stdio만.

## 3. 범용 캔버스 — 신규는 **3종**뿐이다

녹취 요구: *"어떠한 최소한의 숫자의 UI를 제시"*. 최소를 진짜로 지킨다.

조사한 MCP 서버들(dart-mcp, korea-stock-mcp, naver-search-mcp, pykrx-mcp, news-collector, Pulitzer)이 실제로 뱉는 데이터 형상은 7가지였고, 그중 **기존 12캔버스로 이미 커버되는 것이 4가지**다.

| 형상 | 필드 | 처리 |
|---|---|---|
| 시간순 기사 리스트 | title, originallink, description, pubDate, (source) | **신규 ①** |
| 공시 메타데이터 목록 | 회사, 제출일, 공시유형, 제목, 접수번호 | **신규 ①** (같은 형상. 태그만 다르다) |
| 장문 문서 원문 | 전문 텍스트 / TOC + section_id 페이지네이션 | **신규 ②** |
| 수치 시계열 | 일자, OHLCV, 투자자별 순매수 | 기존 #1 · #2 |
| 개체 프로필/룩업 | corp_code, 종목코드, 시장구분, 종목명 | 기존 #5 (일반화) |
| 파생 분석 스코어 | 감성점수, 영향도, 재무비율, 신뢰도 | 기존 #5 (일반화) |
| 임의 스키마 레코드 | 서버마다 제각각 | 기존 #3 (일반화) |

### 신규 ① — **스트림** (시간순 레코드)

뉴스와 공시가 **같은 형상**이다. 하나로 만든다.
- 필수: `ts` · `source` · `title` · `url`. 선택: `summary` · `tickers[]` · `kind`(news/filing/report)
- 밀도 3단: 제목만 / 제목+요약 / 카드. 기본은 **제목만** (soul.md §4 — 기본값은 극단적 미니멀)
- 색: 없음. 종목 태그도 무채색. 등락 적/청은 스트림에 등장하지 않는다

**실측 필드 매핑 — "같은 형상"은 개념 수준에서만 참이다. 필드명은 전혀 다르다.**

| 스트림 필드 | 뉴스 (`search_news`) | 공시 (`get_disclosure_list`) |
|---|---|---|
| `ts` | `pubDate` — **RFC 822**, 항상 `+0900` | `rcept_dt` — **YYYYMMDD, 시각 없음.** 정렬은 `rcept_no`(시퀀스) 보조 필요 |
| `source` | `originallink` 도메인 | **없음.** 게이트웨이가 `"DART"` 부여 |
| `title` | `title` | `report_nm` (`[기재정정]` 접두사 섞임) |
| `url` | `originallink`(원문) / `link`(네이버 사본) | **없음.** `dart.fss.or.kr/dsaf001/main.do?rcept_no=…` 조합 필요 |
| `summary` | `description` | **없음** |
| `tickers[]` | 없음 | `stock_code` |
| `kind` | 항상 `"news"` | `corp_cls` 또는 `report_nm` 파싱 |

→ **게이트웨이에 정규화 어댑터가 반드시 필요하다.** 소스마다 `ts` 정밀도(초 vs 일)와 `url` 유무가 다르다.

**★ 뉴스 `title`·`description`은 sanitize 필수.** 실측:
- **`<b>` 태그가 100/100 아이템 전부에** 들어 있다 (검색어 하이라이트)
- HTML 엔티티(`&quot;`·`&amp;`)가 24~26%에 등장

```
"title": "&quot;성인 5명 중 1명은 주주&quot;…800만 개미들 <b>삼성</b>에 몰렸다"
```
태그 스트립 + 엔티티 언이스케이프를 렌더 전에 걸지 않으면 raw `<b>`가 화면에 노출된다.

### 신규 ② — **리더** (장문 1건) ★ 실측으로 재설계됨

> **정정**: 초안은 *"소용량=전문, 대용량=TOC+`section_id` 페이지네이션"* 이라고 썼다. **실측에서 재현되지 않았다.**
> `get_disclosure`의 `inputSchema`는 `rcept_no` 하나뿐이고 `additionalProperties: false`다. `section_id`를 보내도 조용히 무시된다.
> **문서 크기와 무관하게 항상 전문을 한 번에 반환한다** — 소용량 4,517자, 대용량 **1,042,014자**. 근거: `spike/mcp-client/CAPTURE-S2B-jjlabsio.md`

**따라서 리더는 서버가 아니라 클라이언트가 문서를 쪼갠다.**

- 좌: TOC / 우: 본문 / 하단: AI 요약 — **TOC는 클라이언트가 JSON 트리에서 유도한다.** 서버가 안 준다
- **AI가 요약에서 인용한 구간은 본문에서 하이라이트된다.** 근거 없는 요약을 못 쓰게 만드는 구조적 강제
- 1MB급 JSON을 통째로 받는다. "TOC 먼저, 절은 지연 로드" 설계는 **불가능하다**

### 서버 교체로 해결됨 — `chrisryugj/korean-dart-mcp` ★

**같은 접수번호(`20260713000395`)로 직접 대조한 결과:**

| | `jjlabsio` | **`chrisryugj/korean-dart-mcp`** |
|---|---|---|
| 형태 | DART XML → JSON transliteration, 4,517자 | **깔끔한 마크다운, 2,102자** |
| 표 | `TABLE→COLGROUP→TBODY→TR→TD` 트리 | `\|...\|` 마크다운 표 |
| 원시 XML 태그 누출 | **있음** — `<TE ALIGN="RIGHT" ...>81,003,271</TE>` 가 값 안에 박혀 옴 | **0건 / 400,000자** (대용량 사업보고서 검사) |

→ **리더 캔버스는 표준 마크다운 렌더러 하나면 된다.** 두 갈래 처리 요구사항이 사라졌다.
`raw`(원본 XML) · `text`(태그 제거) 포맷 옵션도 있어 "원문 그대로 보기" 토글도 쉽다.

**남는 제약 — 서버를 바꿔도 안 사라진다:**

1. **`truncate_at` 기본값이 100,000자다.** 삼성전자 사업보고서는 마크다운 변환 후 **636,059자**(원본 XML 8,978,836자) — 기본값이면 **84%가 잘린다.** 게이트웨이가 명시적으로 크게 잡아야 한다
2. **첨부파일(HWP/PDF) 마크다운 변환은 광고와 달리 동작하지 않는다.** 실측 2/2 `EMPTY_INPUT` 실패.
   원인 규명됨 — DART 다운로드가 `Referer`를 정확히 요구하는데(`pdf/download/main.do?...`), 틀리면 **HTTP 200에 0바이트**를 준다. 서버가 그 0바이트를 파서에 넘겨 터진다(재현율 100%)
   → **리더는 "본문은 마크다운 렌더, 첨부는 DART 뷰어 링크만 노출"로 설계한다.** `get_attachments mode=list`는 100% 성공하므로 `download_url` 링크 노출은 안전
3. **당일 접수 실패 조건**을 `chrisryugj`로는 재현하지 않았다. 같은 DART zip 경로를 타므로 적용될 가능성이 높다 — W1 전 재확인 필요

**실패 조건도 밝혀졌다.** "대용량이라 실패"가 아니라 **"DART 문서저장소에 원문 zip이 존재하는지"** 가 성패를 가른다.
당일 접수 공시 8건이 전부 실패했다 — DART가 zip 대신 `{"status":"014","message":"파일이 존재하지 않습니다."}` XML을 반환하고, 서버가 그걸 검증 없이 unzip하다 `ADM-ZIP` 예외를 던진다(서버 에러 핸들링 결함).
→ **리더는 "문서 미존재/처리 지연"을 별도 에러 상태로 구분해 표시해야 한다.**

### 신규 ③ — **타임라인** (가격축 × 이벤트) ★

**투자정보에서 가장 가치가 큰 화면이고, MCP 없이는 불가능한 유일한 화면이다.**
스트림(①) × 시계열(기존 #1)의 합성 — 주가 차트 위에 뉴스·공시가 핀으로 박힌다.

- 키움 TR만으로는 만들 수 없다. **MCP를 붙이는 이유 그 자체를 시각적으로 증명하는 캔버스**
- 핀 클릭 → 리더(②)가 옆에 뜬다. 캔버스가 캔버스를 부른다
- 핀 밀도가 높으면 클러스터링. 겹친 핀은 정직성 위반

### 신규 ④ — **공통 테이블** (스키마 불특정 레코드) ★ 격상됨

당초 "`#3 랭킹 테이블`의 일반화"로 적었으나 **방향이 반대였다. 공통 테이블이 부모고 랭킹 테이블이 자식이다.**

```
자유 캔버스     ← 형상 자체를 모름               (최후의 탈출구)
공통 테이블     ← 레코드인 건 알되 스키마 모름    ★ 기본값
전용 캔버스     ← 형상·스키마 다 앎 (랭킹/호가/타임라인/체결로그)
```

> **선행사례 경고**: 축 B(자연어→시각화 자동생성→저장)는 **OpenBB Workspace가 이미 구현했다.**
> *"the agent writes it… a functioning widget, a dashboard, or even a full app… The artifact lives in the Workspace"* — 적대적 검증을 통과한 유일한 covered 판정이다.

### S1 — Electron 유리 · 모션

Electron 43.4.0 / Win11 26200 실측.

| 조합 | 뒤가 비치나 | 블러/굴절 |
|---|---|---|
| `transparent:true` 만 | 예 | **아니오** — 완전 투명, 블러 없음 |
| **`backgroundMaterial:'acrylic'` 만** | **예** | **예** ← 이거 하나로 충분하다 |
| 둘 다 | 예 | 예 (b와 육안 동일) |
| CSS `backdrop-filter` 만 | **아니오** | 페이지 내부 콘텐츠에만 걸림(무의미) |

**두 결론:**
1. **충돌하지 않는다.** 다만 **같이 쓸 필요가 없다** — `backgroundMaterial:'acrylic'` 단독으로 "뒤가 비치며 블러"가 성립한다. `transparent`는 블러 없는 완전 투명 레이어가 필요할 때만 추가한다.
2. **CSS `backdrop-filter`만으로는 데스크톱을 절대 못 비춘다.** 창이 OS 레벨로 불투명이면 blur는 페이지 내부에만 걸린다. **리퀴드 글래스는 CSS만으로 흉내 낼 수 없다** — 실측으로 확정.

**모션** — `clip-path: circle()` 확장 + `backdrop-filter` 30px→6px 변조(페이드 미사용). 창 크기 애니메이션 없음.
부하 조건(SVG 300포인트 차트 + 100행 테이블) 하에서:

| | p50 | p95 | max | 드롭 |
|---|---|---|---|---|
| 확장 | **16.7ms** | 33.3ms | 33.4ms | 2회 / 550ms |
| 수축 | 16.7ms | 16.8ms | 16.8ms | **0회** |

**배치** — 1560×800 + 1560×204를 1920×1200 화면에 **축소 없이** 배치. `getBounds()`로 두 창의 완전 독립 이동·리사이즈 확인.

*미해결*: 실제 데스크톱 합성 스크린샷이 간헐 실패(이 세션이 데스크톱을 다른 프로세스와 공유 중). 수치 데이터는 Chromium 내부 측정이라 영향 없음.

#### `CallToolResult` 파싱 우선순위 — 확정

```

2. structuredContent    → 있으면 이걸 신뢰   (@drfirst, server-everything)
3. content[0].text      → json.loads() 시도  (pykrx 전 툴이 이 경로)
4. 파싱 실패            → 순수 텍스트. 리더 캔버스 원문 후보
```

**서버마다 다르다.** `pykrx-mcp`(FastMCP)는 output schema가 없어 `structuredContent`가 **항상 null**이고, `@drfirst`(Node SDK)는 채워진다. 게이트웨이는 둘 다 처리해야 한다.

#### 레지스트리 설계 — 실측이 확정한 3건

| 발견 | 설계 귀결 |
|---|---|
| `pykrx-mcp` · `@drfirst/korea-stock-mcp` · `jjlabsio` 미러 **셋 다 `serverInfo.name`이 `korea-stock-mcp`류로 겹침** | **`serverInfo.name`을 네임스페이스 키로 쓰면 안 된다. 사용자가 등록 시 부여하는 별칭이 키다** |
| 92자 툴명으로 `^[A-Za-z0-9_-]{1,64}$` 위반 재현 | 레지스트리가 **등록명 길이를 제한하거나 해시 축약**해야 한다 |
| `pykrx-mcp`가 `serverInfo.version`에 **자기 버전이 아니라 mcp SDK 버전(1.28.1)** 을 노출. `@drfirst`도 npm 버전(1.0.5)과 보고값(0.1.0)이 다름 | **`serverInfo.version`을 곧이곧대로 믿고 표시하면 안 된다** |

#### 신규 리스크 — 한글 인코딩 손상

`@drfirst/korea-stock-mcp`가 반환하는 한글이 `U+FFFD` 혼합으로 **비가역 손상**된다. `content[0].text`와 `structuredContent` 양쪽 다. 2회 재실행 동일 재현.

- **방향성**: 클라이언트→서버는 정상(우리가 보낸 `"삼성전자"`를 서버가 정확한 UTF-8로 재인코딩해 씀). **서버→클라이언트 방향만 손상.**
- `pykrx-mcp`는 **정상**(초안이 손상된다고 썼으나 검증에서 재현 실패 → 정정됨)
- 근본 원인 미규명 — W1에서 이 서버 하나를 대상으로 추가 검증 필요

→ **레지스트리에 "등록 시 인코딩 스모크 테스트"를 넣어야 한다.** 한글 종목명을 왕복시켜 `U+FFFD`가 섞이면 경고.

#### 미확인으로 남은 것

**`jjlabsio/korea-stock-mcp`의 `get_disclosure` 실제 응답을 캡처하지 못했다.** DART 키뿐 아니라 **KRX 키도 요구**한다(README에 없던 사실 — §5 리스크가 필요 환경변수 목록에도 적용됨을 실증). 키 없이 호출된 건 `get_today_date` 하나뿐.

→ **신규 캔버스 ② 리더의 데이터 근거가 여전히 없다.** W3 전에 키를 발급받아 재시도해야 한다.
신규 ① 스트림(뉴스/공시 시간순)과 ③ 타임라인 합성도 이번 캡처로는 미검증 — `naver-search-mcp` / `dart-mcp`를 별도로 붙여야 한다.

#### 설치 난이도 — §2 "패리티는 공짜" 주장 성립

- **npx 서버**: `npx -y <패키지>` 한 줄. **클로드 데스크탑 스니펫 붙여넣기가 실제로 통한다** — 확인
- **Python 서버**: `npx` 같은 원커맨드가 없다. `uvx` / `uv tool install` 필요 → **일반 사용자에게 진입장벽이 뚜렷이 높다.** 레지스트리가 `uvx <패키지>`를 command로 **자동 제안**해야 실사용 가능

#### 스펙 버전 — §5 리스크 정정

실측 서버 3개가 전부 **`protocolVersion: 2025-11-25`** 를 보고했다. §5 리스크 표의 *"2025-06-18 기준으로 짓는다"* 는 **재검토가 필요하다.** 배포된 서버들이 이미 그 다음 리비전을 말하고 있다.

### 게이트웨이 구현에 직결되는 실측 4건

**① `structuredContent`는 예외지 규칙이 아니다.**
서버 3개 중 2개가 전부 `null`이다 — `jjlabsio` 8툴 전부, `naver-search` 전부(outputSchema 미선언). `@drfirst`만 채운다.
→ **`content[0].text`를 `json.loads()` 하는 경로가 주경로다.** structuredContent 우선 규칙은 유지하되, 폴백이 실제로 대부분을 처리한다.

**② `protocolVersion`이 서버마다 다르다.**
`server-everything` → `2025-11-25`, `naver-search` → `2025-06-18`.
→ 게이트웨이는 **버전 혼재를 전제**해야 한다. 단일 버전 가정 금지.

**③ `corp_code` 정규화가 필수다.**
`get_corp_code`가 `126380`을 **숫자로** 반환해 선행 0이 소실된다(정상값 `"00126380"`). 그런데 하위 호출은 전부 `minLength:8` 문자열을 요구한다.
→ 정규화 없이 넘기면 `MCP error -32602: Expected string, received number`로 즉시 실패한다. **게이트웨이가 `str(x).zfill(8)` 처리해야 한다.**

**④ 인코딩 손상은 `@drfirst` 하나에 국한된 것으로 보인다.**
`naver-search`(Node)·`pykrx`(Python)·`jjlabsio`(Node) 전부 `U+FFFD` 0건. 반증 사례가 셋으로 늘었다.
→ "Windows 자식 프로세스 stdio 문제"라는 가설은 약해졌고, **해당 서버 구현 문제일 가능성이 커졌다.** 근본 원인은 여전히 미규명.

### NAVER 크레덴셜 — API HUB 확정

| 조건 | 결과 |
|---|---|
| `NCP_APIGW_API_KEY_ID` + `NCP_APIGW_API_KEY` 만 | **성공** |
| `NAVER_CLIENT_ID` + `NAVER_CLIENT_SECRET` 만 (같은 값) | **401** `NID AUTH Result Invalid (1000)` |
| 둘 다 | 성공 (HUB 우선) |

엔드포인트가 물리적으로 다르다 — 레거시 `openapi.naver.com/v1/search` vs HUB `naverapihub.apigw.ntruss.com/search/v1`, 헤더도 `X-Naver-Client-*` vs `X-NCP-APIGW-API-KEY*`.
**응답 필드는 레거시와 동일하다** — 이관에 따른 필드 변경 없음.

### KRX — "미승인 대기" 확정. **"미지원" 가설은 기각됨** ★

대조군 실험이 판정했다. 같은 엔드포인트에 세 조건으로 호출:

| 조건 | `respMsg` | 바이트 |
|---|---|---|
| **실제 키** | **`"Unauthorized API Call"`** | 52 |
| 가짜 키 (`INVALID_TEST_KEY_12345`) | `"Unauthorized Key"` | 47 |
| 키 헤더 없음 | `"Unauthorized Key"` | 47 |

**세 조건이 바이트 단위로 갈렸다.** 엔드포인트가 죽었거나 키를 안 본다면 셋이 같아야 한다.
→ **서버가 실제 키를 유효한 등록 키로 인식하고 있다.** 문구도 "키"가 아니라 "**이 API 호출**"이 미승인이라고 말한다.

호스트·경로도 살아 있다:
- `data-dbg.krx.co.kr` DNS 정상 (Akamai CDN 대역 — 실서비스 인프라)
- 인증 없이 호출 → **401이지 404가 아니다.** 경로가 존재하고 라우팅되어 인증 단계까지 도달
- `openapi.krx.co.kr`에 같은 경로는 404 → **포털(가입·발급)과 실행 호스트가 분리된 정상 아키텍처.** `dbg`는 죽은 스테이징이 아니다
- 카탈로그에 8개 API 등재, **최근 수정 2026-01-16.** 종료·이관 공지 없음

**키 2개로 재확인 (2026-08-15)** — 사용자가 인증키를 교체한 뒤 재실행. **결과 동일**.
두 키 모두 `"Unauthorized API Call"`, 가짜 키는 `"Unauthorized Key"`. → **키 문제가 아니다.**

**전 카테고리 21개 엔드포인트 전수 스캔 — 승인된 API가 하나도 없다.**
`sto`(8) · `idx`(3) · `etp`(3) · `bon`(2) · `drv`(2) · `gen`(2) · `esg`(1) 전부 `"Unauthorized API Call"`.
**404가 하나도 없다** — 21개 경로가 전부 실존한다(카탈로그가 주식 8개보다 넓다). 근거: `spike/captures/KRX-newkey-fullscan.json`

**승인이 2단계다** — ① 인증키 신청 승인(통과함) ② **API별 활용신청 승인**(하나도 안 됨).
→ **`openapi.krx.co.kr` 마이페이지 → 이용현황에서 활용신청이 접수돼 있는지 확인하라.** 서버 응답만으로는 "신청 안 함"과 "신청했고 대기 중"이 구분되지 않는다. **전 카테고리가 0건인 것으로 보아 신청 자체가 안 된 쪽에 무게가 실린다.**

### ③ 타임라인 가격축은 막혀 있지 않다

`pykrx-mcp`가 **키 없이** `get_stock_ohlcv`를 준다(실측 재확인). **KRX 승인을 기다리지 말고 지금 착수 가능하다.**

단 완전 대체재는 아니다. 8툴 중 **2개만 성공**했다:

| 성공 | 실패 (6개) |
|---|---|
| `get_stock_ohlcv` · `get_market_ticker_name` | `get_market_ticker_list` · `get_market_fundamental_by_date` · `get_market_cap_by_date` · `get_market_trading_value_by_date` · `get_etf_ohlcv_by_date` · `get_etf_ticker_list` |

실패 원인은 **KRX 키와 무관**하다 — `pykrx`가 스크래핑하는 `data.krx.co.kr`이 `HTTP 400 "LOGOUT"`을 반환한다(라이브러리 세션 버그, 근본 원인 미규명). 날짜를 바꿔도 동일 재현.

그리고 `get_market_ticker_list`는 **성공하더라도 종목명을 안 준다** — 소스 추적 결과 내부적으로 ticker+name을 받고도 `s.index.to_list()`로 이름을 버린다. **종목명 대량 조회는 pykrx-mcp로 불가능하다.**

→ **KRX 키를 포기하지 말고 병행한다.** 승인되면 상장일·액면가·ISIN·거래대금·시가총액 등 pykrx가 못 주는 필드까지 열린다.
