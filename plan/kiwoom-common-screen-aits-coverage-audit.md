## 0. 결론 요약

1. **배정 커버리지는 100%다 — 기계 증명 3중 검증.** in-scope 299개(301 − oauth 2) 전부에
   카드가 정확히 하나씩 배정돼 있고(facts 114 / table 121 / compound 29 / event 23 / action 12),
   셀렉터 도달 가능 우주와의 대사도 완전하다(§2).
2. **카드 최소화 판정: 신규 카드 0종, in-scope는 5종으로 충분, 6종 유지가 정본.**
   StatusCard(2)는 oauth 전용이라 사용자 제외 기준을 적용하면 감사 범위 밖이다. 축소(예:
   Compound를 Facts+Table 합성으로 격하)는 명목상 카드 수만 줄이고 렌더러 조합은 동일하므로
   하지 않는다 — 재설계 금지 확정 결정(§4)과도 일치한다(§6).
3. **AITS 기능 커버는 "대부분 + 갭 5건"이다.** 갭은 전부 이유가 확정됐고, 어느 것도 새 카드
   종류를 요구하지 않는다 — 카드 **계약의 개정** 2건과 **판정 대기** 3건이다(§5).
4. **"이질감은 이미 흡수 가능하다"는 서술은 반박으로 사망했다.** 흡수 규칙 6행은 코드 0건의
   미착수 계획(G001.5 = 대기)이고, 감사 중 실측 결함 2건이 새로 확정됐다 — ka10007 detail
   9그룹의 title TR ID 노출(zero-tolerance 위반), ka10173 이종 메시지 병존(규칙 사각지대)(§7).
5. **AITS 실측이 우리 설계를 예상 밖의 방식으로 지지한다**: AITS "시세표"는 다종목 테이블이
   아니라 단일 종목 스칼라 그리드(= FactsCard 동형)이고, "실시간체결"은 append 로그가 아니라
   최신값 갱신 히어로 패널(= EventCard FID 표시 영역 동형)이며, "조건검색 빌더"는 AITS에도
   없었다(저장 조건식 뷰어뿐) — canvas-taxonomy #11은 신규 발명이었다(§3).

## 3. AITS 실측 인벤토리

집계 재확인: 화면 53 · screenId 64 · TR 208 전부 54 screenId에 매핑(미매핑 0) · 골든 116케이스 ·
카드 kind 6종(market 39 / stock 32 / ranking 24 / account 7 / chart 5 / sig 1, `expected` 기준).

**카탈로그 드리프트 3건(AITS 내부 결함, 우리 감사의 캐비엇):** ① matrix가 참조하는 screenId 2개
(`ITS-QTE-CREDIT`, `ITS-SYS-AUTH`)가 catalog 배열에 없음 ② 1105번 trIds 6개 기재 vs matrix 유도
8개(ka01300/01301 누락) ③ screenId 모집단이 저장소 안에서 3벌(코드 SSOT 196 / docs 화면정의 80 /
카탈로그 64)로 갈린다. **TR 차원 조인(208)은 matrix 기준으로 안정적이므로 감사는 TR 차원으로 했다.**

**화면 명칭이 실형상을 오도하는 함정 3건(.svelte 실측):**
- "시세표"(TR 15) = 다종목 테이블이 아니라 **단일 종목 키-값 스칼라 그리드** → FactsCard 동형
- "실시간체결"(TR 8) = append 로그가 아니라 **최신 틱 스냅샷 히어로 + 1회 플래시** → EventCard의 FID 표시 영역 동형
- "조건검색" = 빌더 없음. **저장 조건식 목록 뷰어 + 번호 실행 + 실시간 토글**

## 6. 최소화 판정 — 답 ④

- **신규 카드 0종.** AITS 64 screenId의 카드 kind도 6종(market/stock/ranking/account/chart/sig)
  으로 접혀 있었고, 대응은 market·stock·account→Facts/Compound, ranking→Table, chart→Compound(+렌즈),
  sig→Event로 닫힌다.
- **in-scope(사용자 제외 적용)는 카드 5종으로 충분** — StatusCard는 oauth 2건 전용이라 제외
  기준 밖. 카드 체계 전체로는 6종 유지(oauth 화면 자체는 앱에 필요).
- **추가 축소는 하지 않는다.** Compound(29)를 "Facts+Table 합성"으로 격하하면 명목 카드 수만
  줄고 렌더러 조합·상태·검증 게이트는 동일하다. manifest가 6분할 함수관계를 기계 증명하고
  있고, 재설계 금지가 확정 결정이다.
- 12캔버스(카드 12종, canvas-taxonomy)는 **표현 계층 렌즈**로 유지 — 완전성 계층이 아니므로
  최소화 대상 아님(spec §9 확정). 이번 감사로 그 목록 중 "조건검색 빌더"는 AITS에조차 없던
  발명임이 확인됨 — 렌즈 라운드에서 우선순위 재고 근거.
